## Introduction

### Why this spec exists

Before this spec, a fault in this fork went to one of five places, or to none, depending on which
process had it:

- **`storage/logs/ff3-cli-server-YYYY-MM-DD.log`** — Laravel's daily file for the web process
  (`config/logging.php`, channel `daily`, path `ff3-<PHP_SAPI>.log`). It holds a fault together with
  roughly 260 ERROR and 383 WARNING lines on a normal day, most of which are answers, not faults: a
  duplicate transaction, a validation refusal, a missing OAuth key.
- **`storage/logs/ff3-cli-YYYY-MM-DD.log`** — the same, for `php artisan` commands.
- **`~/T/_firefly_iii/server.log`** — the web process's stdout and stderr, captured by `ffx up`.
- **`~/T/_firefly_iii/cli.err`** — only for `ffx`.
- **`~/T/_firefly_iii/mcp.err`** — only for the MCP server.
- **Split in two, with the halves unjoined:**
  - A throw inside a batch op is reported by the **sub-request's** routing pipeline
    (`MirrorController::dispatchInternal()` → `$router->dispatch()` → `report()` then `render()`),
    so it lands in the daily file under the sub-request's route, not under `/machine/v1/batch`. The
    op comes back as an `internal` envelope, and `BatchController.php:307` then throws a second
    `MachineException('internal', 'The operation failed.')` with no cause, which
    `MachineExceptionHandler::report()` declines. The rare direct throw that reaches the catch at
    `BatchController.php:289` drops its original throwable entirely. Nothing ties the two halves to
    the `ffx` call that asked.
- **Nowhere at all:**
  - The browser has no `window.onerror`, no `unhandledrejection` listener, no axios interceptor and
    no `$(document).ajaxError`. Twenty-six `.catch` sites in the v3 bundle go to `console.error` or
    are swallowed. If `boot/bootstrap.js` fails, it prints one `console.error` and the page silently
    never starts.
  - Neither Node runtime has an `uncaughtException` handler. `ffx`'s `loadConfig()` and
    `initLogger()` run outside any try block.

On top of that, **every hint that tells the operator where to look is wrong.** Code, tests and specs
name `storage/logs/laravel.log` 10 times, point at `ffx logs --laravel` 5 times, and name `cli.err`
or `mcp.err` twice. `laravel.log` is the `single` channel's path, and this
install never writes it. So the honest answer to _"what went wrong yesterday at 4 pm?"_ was _"it
depends which process, the hint points at a file that does not exist, and the browser never told
anyone."_ A program that holds the operator's ledger cannot be allowed to fail like that.

### Where this spec fits

The fork has three front doors, and each already has a spec:

- the browser at `http://127.0.0.1:7373/` ([accounts.mdx](./accounts.mdx) for signing in);
- the `ffx` CLI ([cli.mdx](./cli.mdx));
- the `firefly_iii` MCP server ([mcp.mdx](./mcp.mdx)).

The CLI and the MCP sit on the machine plane ([apis.mdx](./apis.mdx)). This spec is not a front
door. It is the floor under all of them: the single fault trail that every process writes to.

It owns three things other specs point at:

- the file `~/T/firefly/error.err`, its format and its privacy rules;
- the canonical hint text, **`The detail is in ~/T/firefly/error.err — ffx logs --errors`**, which
  every `internal` and `upstream_error` answer carries (apis.mdx §5.2, cli.mdx §14, mcp.mdx §12.3);
- the `POST /error-report` ingest route, which is **not** a plane route and is not in
  `/capabilities`.

What it leaves alone:

- `cli.info`/`cli.err` (cli.mdx §15.2) and `mcp.info`/`mcp.err` (mcp.mdx §16.1) keep their jobs, a
  per-tool usage trail and audit. They also start writing every fault to `error.err`, so the
  operator never has to know which tool failed before knowing where to look.
- `~/T/_firefly_iii/machine.audit` (apis.mdx §16.4) keeps its job: it records **what the plane did**.
  `error.err` records **what broke**. A refused write goes to the audit trail. A fault goes to
  `error.err`. They are never merged.
- `~/T/_firefly_iii/server.log` stays the answer for two things that are not faults: the "plane
  armed" line (apis.mdx §3.2) and the password-reset link written by the `log` mailer
  (accounts.mdx §4.1).
- Laravel's daily files under `storage/logs/` stay upstream's. This fork never tells the operator to
  read them to find a fault.

### What the operator gets from it

- **One file to open.** `tail -f ~/T/firefly/error.err`, or `ffx logs --errors --follow`, or
  `just errors`, shows faults from every process interleaved in time order. Each is tagged with the
  surface it came from — `php-web`, `php-api`, `php-machine`, `php-artisan`, `php-queue`, `ffx`,
  `mcp`, `web` — and the source file it came from.
- **A line that answers the question on its own.** Each line has four parts:
  - **what** it was doing: _"handling POST /machine/v1/transactions"_ (op 3 of a batch, run as a sub-request);
  - **where**: `app/Machine/Http/Controllers/TransactionController.php:204`;
  - **what broke**: `RuntimeException: Synthetic failure while dispatching op 3`, with its cause chain;
  - **where in the code**: a stack trimmed to this repo's own frames.
- **Two lines per incident, joined by an id.** When `ffx` gets an `internal` answer, the `[ffx]`
  line and the `[php-machine]` line carry the same `rid=`. `grep rid=7f3a9c01` shows both halves.
  There is exactly one `[php-machine]` line per internal fault, even inside a batch (§4.5).
- **A file that stays readable.** Five hundred identical faults across fifty PHP requests become one
  line plus a count. A duplicate transaction, a 422 on a form, a stealth-404 gate refusal: nothing.
- **A trail that survives a crash.** An out-of-memory fatal in a web request is on disk before the
  process dies.
- **Hints that point at a file that exists.** Every hint the plane, `ffx` and the MCP give for a
  fault names `~/T/firefly/error.err` and `ffx logs --errors`.

### How it works — the idea

**Catching an error is the call site's job. Handling it is the library's job.**

In fork-owned code, a call site writes one line:

```php
ErrorFile::for('app/Machine/Audit.php')->caught('appending to the plane audit log', $e);
```

```ts
errors.caught('running an ffx verb', err, { verb });
```

In upstream code, the call site writes **nothing**. Upstream is never edited to report. Its faults
reach the file through nets the fork already owns: the app-wide exception handler and a listener on
Laravel's own log event.

Everything that makes a fault record useful is done once, centrally, and only when there is a fault:

- deciding whether it is a fault at all, or an answer;
- formatting, and walking the cause chain;
- remembering that this exact throwable has already been written;
- folding a burst of identical faults into one line, across processes;
- redacting secrets and refusing ledger data;
- appending, locking and rotating the file;
- carrying the record out of a browser that has no filesystem.

### How it works — the machinery

1. **Three implementations of one line format.** PHP writes from `app/Machine/ErrorFile/`. Node
   writes from `errorfile/src/`, vendored into `cli/` and `mcp/`. The browser never writes: it
   delivers to PHP. A golden fixture proves PHP and Node produce identical bytes (R16).
2. **PHP has two nets and no upstream edit.**
   - **The handler net.** `MachineExceptionHandler` is already the app-wide `ExceptionHandler`
     singleton, bound by the fork's provider. Its `report()` now calls `ErrorFile::handlerReport()`
     first. That one call sees the HTTP kernel, the routing pipeline, the console kernel, the sync
     queue and PHP fatals.
   - **The log net.** A `MessageLogged` listener sees every `Log::error` on every channel. That is
     how the 188 upstream catch blocks that log and swallow reach the file, sorted into tiers
     T1–T4 (§4.6).
3. **PHP writes synchronously, and folds through a sidecar.** Each web request is its own short-lived
   process under `php -S`, so there is no process to buffer in. The record is appended at report time
   with a bounded lock. Bursts fold in two layers: an in-process table, and the shared
   `~/T/firefly/error.fold` sidecar (§3.5, §4.7).
4. **Node buffers and flushes.** The node sink appends asynchronously, flushes synchronously on
   `fatal`, exit and signals, and rotates at 5 MiB. It is installed by a side-effect module that is
   the **first import** of each runtime's `index.ts`.
5. **The browser batches and beacons.** Two tiny modules, reached by one import line in each of the
   two boot files, install window nets, axios interceptors, the Alpine error handler, a
   `$(document).ajaxError` net for legacy jQuery pages, and a boot watchdog. They send batches to
   `POST /error-report`.
6. **Enforcement.** Two coverage scripts classify every catch site in fork-owned code, and report
   upstream PHP's silent catches for information. A canary per runtime proves each net fires.

### What this spec covers

- The file, its line format, its `app` values and its fold sidecar (§3).
- The PHP library, its tiers, the provider wiring and the ingest route (§4).
- The Node library and how it is vendored (§5), and the browser modules (§6).
- The call-site API in three languages (§7) and the code patterns with before and after code (§8).
- The global nets and the named escape hatches (§9).
- Performance (§10), noise (§11), privacy (§12) and enforcement (§13).
- Measurements (§14), tests (§15), rollout (§16) and upstream-merge cost (§17).
- The **locked** list of re-pointed hints and edits to sibling specs (§18).

It does **not** cover usage and audit logging (`cli.info`, `mcp.info`, `machine.audit`), which stay
where cli.mdx §15, mcp.mdx §16 and apis.mdx §16.4 put them. It does not change Laravel's daily
files, upstream's error pages, or upstream's `MailError` job.

## Goal

> **Every fault that happens in any runtime of this fork is written to `~/T/firefly/error.err`,
> exactly once, and the line alone says what was being done, where, and what broke. Fork-owned code
> reports with one short call per error site; upstream code is reached by nets and never edited;
> and nothing is paid until a fault actually happens.**

Five halves to that sentence, and each is a rule the build is measured against:

| Half             | The rule                                                                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Completeness** | Every runtime has a wired net (§9), and every catch site in fork-owned code reports, rethrows or is marked expected. Upstream PHP is covered by the handler and log nets. Two coverage scripts and fifteen canaries prove it. |
| **Readability**  | A call site is one line. No call site formats, stringifies, redacts, folds, reads a stack or touches the filesystem.                                                                                                        |
| **Performance**  | A request, command or page with no fault makes zero syscalls on `~/T/firefly/`. On the fault path, PHP holds a lock for at most 200 ms and Node never writes synchronously except while dying.                              |
| **Signal**       | A burst is one line plus a count. A refusal is an answer and writes nothing. A normal day with no real fault writes 10 lines or fewer.                                                                                     |
| **Safety**       | No secret and no ledger value is ever written. The file lives outside the repo at mode `0600`. Tests never write the real file. Upstream stays untouched except for two import lines.                                     |

## 1. What we learned from the sister apps

We read the specs and code of four sister apps, in read-only mode. Three of them — the Internal Web
App, We The Citizens and Large File Bridge — converged on the same core: a fault file beside a
general log, rotation at 5 MiB × 5, a control-character guard, and a browser → server bridge. The
fourth, the Actual Budget fork, is this fork's twin: the same machine plane, the same kind of CLI and
MCP, the same private-data boundary. It already did the three-app study and turned it into a spec
and a library. This spec starts from Actual Budget and re-scopes it to PHP.

### 1.1 Actual Budget — the reference (`~/BGit/Bryan_git/actual_budget_bryan/`)

**Spec:** `~/BGit/Bryan_git/actual_budget_bryan/pm/error_err.mdx` (1,677 lines, R1–R14).
**Library:** `packages/error-file/src/` — `core.ts`, `describe.ts`, `redact.ts`, `fold.ts`,
`format.ts`, `node.ts`, `rolling-file-writer.ts`, `browser.ts`, `ingest.ts`, `vite-plugin.ts`, zero
runtime dependencies. AB's `scripts/sync-error-file.mjs` vendors nine of them (including `ingest.ts`)
into `cli/code/src/vendor/` and `mcp/src/vendor/`; this fork vendors eight, dropping `ingest.ts`,
because PHP owns ingest here (§5.4).

**What we take, almost verbatim:**

- the call-site shape `errorFileFor(where).caught(doing, err)`, with `warn`, `expected`, `rethrow`,
  `fatal` and the wrappers `tryOr`, `tryOrAsync`, `reportRejection`, `guard`;
- per-object de-duplication with a `WeakSet`, so a throwable rethrown through four layers is written
  once, by the innermost layer that knew what it was doing;
- the line format, the caps (message 2,000, data 1,000, record 8,000, stack 12 frames, causes 5)
  and `stripControlChars`;
- burst folding on a normalised key over a 60 s window, and a 10-minute WARN fold for transient
  network errors;
- the `RollingFileWriter`: buffered async appends, a synchronous flush only while dying, a real-size
  check before rolling so two processes never both roll;
- the refusal of ledger-shaped data keys, and the rule that a gate refusal is an answer (AB R7);
- the vendored copy with a byte-for-byte drift test;
- a loopback-only ingest route that always answers `204` and never echoes.

**What we change, because Firefly is not Actual Budget:**

| Actual Budget                                             | This fork                                                                                                             |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Every runtime is Node or a browser                        | The main runtime is **PHP**: a fresh process per web request under `php -S`, plus artisan and PHPUnit                 |
| One universal TS package in a monorepo workspace          | A PHP library in `app/Machine/ErrorFile/` **and** a TS library in `errorfile/src/`, sharing one golden fixture         |
| Upstream packages are edited at every catch site          | Upstream PHP is **never** edited. Two nets cover it: the handler and `MessageLogged`                                  |
| A lint rule (a JS lint plugin) enforces catches           | Two scripts: `php-parser` for `app/Machine/**`, the TypeScript compiler API for TS and JS                             |
| Ingest mounted in Vite and in the sync server             | Ingest is **PHP's** `POST /error-report`, with an added same-origin guard                                             |
| `console.error` echo in development                       | `process.stderr.write` only: the MCP `stdout-purity` canary bans every `console.*`                                   |
| Messages pass through as written                          | Upstream log strings carry tokens, emails, amounts and webhook bodies, so text is **scrubbed** (§12)                  |
| Test path chosen by `NODE_ENV`/`VITEST`                   | No `NODE_ENV` here: tests set `FIREFLY_ERROR_FILE` explicitly, and PHPUnit's path is `null`                           |
| Summary text "in the previous 60s"                        | PHP writes summaries lazily, maybe hours later, so the text is "in the 60s window from HH:MM:SS"                     |

**Gap we close:** AB's `slice(0, 8000)` can cut a record mid-frame. This spec cuts only at a
stack-frame boundary (§3.2).

### 1.2 Internal Web App — `~/BGit/all/app/`

**Spec:** `~/BGit/all/app/pm/local_storage.mdx` §6–§8. **Library:** the shared package
`@internal-app/logging` at `code/packages/logging/src/` (`log-channel.ts`,
`rolling-file-writer.ts`, `nest-logger.ts`, `express-transactions.ts`).

**What we take:** the async buffered `RollingFileWriter` (through AB), whose header comment records
why it moved off synchronous writes: 2,771 ms of sync fs time over 4 writes, and 330 "event loop
blocked" warnings a day. The benign-browser-error downgrade (the ResizeObserver loop message). The
`redactUrl` idea: keep parameter names, drop values.

**Gap:** nothing proves every error site reports.

### 1.3 We The Citizens — `~/BGit/act3/we_citizens/`

**Spec:** `~/BGit/act3/we_citizens/pm/errors.mdx` (R1–R13). **Library:** mirrored backend and
frontend copies (`shared/errors.ts`, `burst-coalescer.ts`, `lib/logger.ts`).

**What we take:** the best call-site ergonomics of the three (`loggerFor(ctx).caught(doing, err)`,
about 1,356 calls), the three wrappers, `describeError` with causes before the stack so a length cap
cannot cut them off, the burst coalescer keyed on the message and never on the stack, `sendBeacon`
delivery, and the distinction "a gate refusal is an answer, not a fault".

**Gap:** its two copies can drift, and nothing lints for a bare `catch`. Our vendored copies are
drift-tested (§5.4).

### 1.4 Large File Bridge — `~/BGit/Bryan_git/LargeFileBridge/`

**Spec:** `~/BGit/Bryan_git/LargeFileBridge/pm/debugging.mdx`. **Library:** one file,
`code/packages/backend/src/shared/logging.ts`, built-ins only.

**What we take:** the normalised collapse key (paths → `<path>`, hex → `<hex>`, digits → `#`),
"offline is not a fault", the structured `where`/`doing` fields, and tests that read the bytes on
disk.

**Gap, and the most important lesson:** its spec requires `logError()` at every error site; its code
has 4 such calls against about 660 plain `log.error`/`log.warn` calls. **A rule that nothing checks
does not get followed.** That is why §13 exists, and why the PHP half is built on nets rather than on
asking 1,211 upstream files to change.

### 1.5 What is new here

Five things exist in none of the four sister apps:

1. **Zero-edit capture of a framework's own logging.** Upstream Firefly has 425 `Log::error` and 173
   `Log::warning` call sites. We never touch one. A `MessageLogged` listener sorts them into tiers:
   a real fault with an exception (T2), a bare error string that is probably a fault (T3), an
   expected answer on a named list (dropped), and warnings (dropped unless verbose) (§4.6).
2. **Cross-process burst folding for per-request processes.** A web request under `php -S` lives for
   milliseconds. Folding "the same fault in 500 requests" needs state that outlives the process: the
   `error.fold` sidecar, under a bounded lock, with lazy summaries written by the next writer (§4.7).
3. **Keeping the log net alive when the log level is raised.** Laravel drops a record **before**
   `MessageLogged` if no handler accepts its level. A fork-owned `KeepAliveHandler` accepts error and
   above, writes nothing, and lets the record bubble on, so upstream's own output never changes
   (§4.9).
4. **An origin-guarded, unauthenticated ingest.** The login page has no session, so ingest cannot
   require one. It is loopback-only **and** same-origin, so no other website open in the operator's
   browser can fill the file (§4.10).
5. **A correlation id across runtimes.** `ffx` and `mcp` send `X-Firefly-Request-Id`; the plane
   stamps it on its record; both lines carry `rid=` (§4.8).

## 2. The rules (R1–R17)

Each rule is cited elsewhere by its number. R-numbers are this spec's own; another spec's rule is
qualified, as in apis.mdx R6.

**R1 — Every error site in fork-owned code reports.** "Fork-owned code" means `app/Machine/**`
(excluding `app/Machine/ErrorFile/` itself), the fork's artisan commands under
`app/Console/Commands/Machine/**` (today `JsonTranslations.php`, `firefly-machine:json-translations`),
`cli/code/src` (excluding `vendor/`), `mcp/src`
(excluding `vendor/` and `canary/`) and the browser glue `resources/assets/v3/js/support/error-file-app.js`.
Each catch, `.catch()` or rejection handler there does one of: call a `Site` or `ErrorFile` method or
a wrapper; rethrow; call `report($e)`; return `Promise.reject`. Upstream code is covered by the nets
(§9) and is **never** edited to report. The error-file libraries themselves — `app/Machine/ErrorFile/`
(minus its `Canary/`), `errorfile/src`, every `vendor/error-file/` copy and the browser core
`support/error-file.js` — are **excluded** from R1 in both coverage scripts, exactly as Actual Budget
excludes `packages/error-file/src/`: their catches are the R11 fallbacks (one stderr write, one
`console.warn`), which by design never report. This narrows D8's enforced scope and is recorded as
V9 (§16.5).

**R2 — One line per site.** `doing` is a literal gerund phrase with no trailing period:
`'appending to the plane audit log'`, not `'Failed to append.'`. Both coverage scripts check the literal
against `/^[a-z][A-Za-z0-9 ,'-]*[A-Za-z0-9]$/` (`badDoing`, §13.1, §13.2). `where` is a literal. The call site
never formats, redacts, reads a stack or touches the filesystem. Dynamic parts go in `data`, so the
fold key stays stable.

**R3 — Zero work until a fault.** A request, command or page that does not fault makes **zero**
syscalls on `~/T/firefly/`. `ErrorFile::for()` and `errorFileFor()` store a string. The listener's
first statement is one array lookup on the level.

**R4 — Each throwable is written once.** PHP marks it in a `WeakMap` per request or process. Node
and the browser use a `WeakSet`. A primitive throwable (a thrown string) cannot be marked, so the
fold (R10) handles it.

**R5 — Rethrow keeps the object.** `rethrow()` writes the record, then throws **the same instance**,
never a wrapper, so `instanceof MachineException`, `CliError.exit` and `ToolError.code` keep working.
Enforced by `SiteTest` and the errorfile core test (§15).

**R6 — Expected is not an error.** `expected()` records nothing unless
`FIREFLY_ERROR_FILE_VERBOSE=1`. It is still required at the site, so a reader sees that the author
**decided** the failure was expected, and the coverage script can prove the decision was made.

**R7 — A refusal is an answer, not a fault.** Each of these writes nothing:

- a plane gate refusal (a response is returned, never thrown: stealth 404, byte-identical 401,
  `write_disabled`);
- a `MachineException` with any code other than `internal` or `upstream_error`;
- anything upstream's `$dontReport` (or Laravel's internal list) declines to report — **including**
  the second, bare `Log::error($e->getMessage())` that `Handler::render()` writes for it at
  `Handler.php:216` (the written-set, §4.5 step 0);
- a `CliError` whose `code` is not `internal` or `upstream_error`, including every exit 2–6 and a
  `doctor` FAIL — **except** a bring-up failure (exit 5), which is a fault and is written by N14
  (§5.7); `reportError()`'s later `expected()` for that same object is a `WeakSet` no-op; and
  **except** a plane-call timeout, which is written as a folded WARN (below);
- a `ToolError` whose code is not `internal` or `upstream_error`, and a `ConfigError`;
- an upstream log line on the expected-prefix list (§4.6), such as `Duplicate of transaction #…`;
- a browser HTTP 401, 404, 419, 422 or 429.

A **plane-call transport timeout** is neither an answer nor an ERROR, and both Node runtimes classify
it the same way: `ffx`'s `CliError` and `mcp`'s `ToolError('upstream_error')` both carry the
`ETIMEDOUT` `ErrnoException` as their `cause`, both classifiers check that transient cause first and
call `warn`, the §5.2 transient rule folds it to one WARN per 10 minutes, and both hints carry **H**
(§5.7; §18.1 H7, H13).

**R8 — The browser never touches the disk; it delivers** to `POST /error-report` (§4.10), which PHP
owns and writes.

**R9 — A fault survives the crash that caused it.** PHP writes synchronously at report time and
never in `terminating()`, because a fatal never reaches it. A FATAL bypasses every fold, raises the
memory limit on an out-of-memory as the **first** statement of `MachineExceptionHandler::report()`
(before `ErrorFile` is even autoloaded, and before any describe, redact or context work), and is
never stopped by a stale busy flag (§4.7). Node flushes synchronously on `fatal`, exit and signals. The
browser sends a beacon on `pagehide`.

**R10 — A burst is one line.** The fold key is `app, where, doing, class, normalised message`, over
a 60 s window. The first occurrence is written through; the rest are counted; one summary line
follows. PHP folds in two layers (L1 in process, L2 in the `error.fold` sidecar) and writes the
summary lazily. A FATAL is never folded. A transient Node network error folds per 10 minutes at WARN.

**R11 — The file never takes the app down.** Every path in every library is total. The fallback for
a failed write is one stderr line per process, then silence. The library never calls `Log::`,
`report()`, `console.*` or `echo`, never recurses (a `busy` flag stops re-entry), and never reports
its own delivery failure. Lock waits are bounded at 200 ms.

**R12 — No secrets and no ledger data** (§12). The `Redactor` enforces it, not the call site. The
library never reads a request body, query string, cookie, a log context array (other than
`context['exception']`) or a trace frame's `args`, and it reads **no header except these named
ones**: `X-Firefly-Request-Id` and `X-Firefly-Client` (in `Context.php`, which reads both itself with
`$request->header(…)` and does **not** call `Audit::caller()`, whose header read sits outside the
fenced directory), and the ingest gate's `Host`, `Origin`, `Sec-Fetch-Site`, `Content-Type` and
`Content-Length` (in `Http/ErrorReportGate.php`). The only body it reads is the ingest body, from
`php://input` with a 65,537-byte cap, in `Ingest.php`. `SourceCanaryTest` forbids every header,
cookie, server-variable and body accessor (§4.1) and allowlists exactly those files and calls.

**R13 — Tests never write the real file.** Under PHPUnit, `Paths::errorFile()` ignores the
env-derived `errorfile.path` entirely and honours **only** a path a test set explicitly:
`ErrorFile::usePath()` in process, or the test-only `errorfile.test_path` key
(`FIREFLY_ERROR_FILE_TEST_PATH`), which only a spawned child's explicit env sets. With neither, the
path is `null` and nothing is written. `phpunit.machine.xml` also force-blanks `FIREFLY_ERROR_FILE`
and `FIREFLY_ERROR_FILE_TEST_PATH` as both `<env>` and `<server>` entries, so a shell export cannot
leak in either way. A child process a test spawns gets an explicit sandbox path (§15). Node test harnesses set
`FIREFLY_ERROR_FILE` for children and pass an explicit `file:` in process (§15). Canaries refuse to
run without an explicit path. D10's "tests set a temp path via `config("errorfile.path")`" is
replaced by this seam; the reason and the revert are V8 (§16.5).

**R14 — `where` is repo-relative.** An explicit site passes a literal path such as
`app/Machine/Audit.php` or `cli/code/src/main.ts`, with no line number, which a reader pastes
straight into an editor. Both coverage scripts fail a literal that is not the file's own
repo-relative path (`wrongWhere`, §13.1, §13.2). A PHP net gives the origin as `path:line`. A browser net gives the page
path template.

**R15 — Upstream stays untouched except for the two boot lines.** The class-A upstream delta is
exactly the set in §17. Every upstream assumption the design leans on is pinned by
`UpstreamAnchorsTest` or `ExpectedListDriftTest`, and a wording change upstream fails safe: it adds
noise, and never leaks or loses anything.

**R16 — One line format, two implementations, one golden file.** `errorfile/fixtures/golden-*` is
asserted byte for byte by PHP's `LineFormat` and by TypeScript's `format.ts`.

**R17 — Every fault hint names the file.** The canonical hint is
**`The detail is in ~/T/firefly/error.err — ffx logs --errors`**, used verbatim in every place that
§18 lists. It contains no `stack` and no home-directory path, so it passes the envelope tests. The
§18 R17 check (a fixed-string grep per hint row, plus `EnvelopeTest` and assertions in the cli and
mcp suites that an `internal` answer's hint `===` **H**) enforces it.

### 3.2 The line (LOCKED)

```
[ts] [LEVEL] [app] [where] doing — <error> {k=v k2="v with space"} | cause: Name: message (code=…)
    at frame
```

A synthetic example:

```
[2026-09-21T18:41:02.118Z] [ERROR] [php-web] [app/Repositories/Account/AccountRepository.php:212] handling GET /accounts/show/{account} — Illuminate\Database\QueryException: SQLSTATE[HY000]: General error: 5 database is locked (code=HY000) {net=report route=accounts.show rid=3c9d0a1e took_ms=38 pid=4242} | cause: PDOException: SQLSTATE[HY000]: General error: 5 database is locked (code=HY000)
```

The header line has these fields, in order:

| Field     | PHP                                                                                   | Node                                         | Browser (after ingest)                        |
| --------- | ------------------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------- |
| ts        | `Clock::nowIso()`, ISO-8601 UTC to the millisecond                                    | `new Date().toISOString()`                   | the client's ts if ISO-8601 with `Z`, else now |
| LEVEL     | `WARN`, `ERROR`, `FATAL`; `EXPECTED` only under VERBOSE                                | same                                         | `WARN`, `ERROR`                               |
| app       | §3.3                                                                                  | `ffx`, `mcp`                                 | `web`, stamped by the server                  |
| where     | explicit literal; net = origin `path:line` (§4.8)                                     | explicit literal (R14)                       | page path template or fork repo path (§6.4)   |
| doing     | literal, or the net's `handling GET /route/{template}` (§4.8)                         | literal                                      | §6.4                                          |
| separator | ` — `                                                                                 | same                                         | same                                          |
| error     | `FQCN: message (code=…)`; T3 is `Log::<level>: message`; a summary is §3.4's text      | `Name: message (code=… errno=… syscall=…)`   | as sent, sanitised and re-redacted            |
| data      | `{k=v …}`, fixed key order and quoting (below)                                        | same                                         | same, plus `via=php-web`                      |
| cause     | ` \| cause: …`, up to 5, cycle-safe                                                   | same                                         | as sent, sanitised                            |
| stack     | up to 12 lines `    at Class->method (path:line)`                                     | up to 12 V8 frames, repo-relative            | up to 24 lines × 400 characters              |

**Headline class names.** PHP writes the fully qualified class name without the leading backslash
(`Illuminate\Database\QueryException: …`), so two different `Exception` classes stay distinct and
`grep` is unambiguous. Node writes `err.name`. The ` (code=…)` suffix is added when PHP's
`getCode()` is non-zero or non-empty; Node appends AB's `code`, `errno`, `syscall` and `type`.

**The data block.**

- Keys come in a fixed order. Call-site keys come first, in insertion order. Context keys follow,
  only where the key is absent, in the order `net route status code caller rid took_ms during via
  pid`. PHP emits `rid`, `took_ms` and `caller` only for an HTTP record (SAPI `cli-server`, or a
  current route), and a FATAL never carries `took_ms`: an artisan or queue record has no request to
  correlate, and the §3.4 goldens pin both facts.
- A value containing a space, `=`, `{`, `}` or `"` is double-quoted, with `"` written as `\"`, so
  `during="running artisan firefly-iii:cron"` stays machine-readable.
- At most 40 keys. A key is cleaned with `[\s={}] → _` and cut to 60 characters. A value is cut to
  300 characters, and the whole block to 1,000.
- Values are scalars only. Anything else prints `[<type> not allowed]`.

**The `net=` key.** Every net-captured record carries exactly one of
`report shutdown log process top window rejection axios ajax alpine watchdog`, telling the
reader which net caught the fault. An explicit call site carries no `net`. `ingest` is a reserved
value that no record carries today: the one record ingest writes in its own name — the lazy
`dropped N browser reports over the ingest limits` WARN — carries `{via=php-web pid=…}` and no `net`
(the §3.4 golden), and a browser record keeps the browser net it arrived with.

A Node explicit site may still stamp `net`: `errorFileFor(where, { net: 'process' | 'top' })`
(§7.2) adds it as a context key after the call-site keys and before `pid`. That is how the process
nets (`node.ts`, N11/N15) and the top-level classifiers (N12, N13, N16, N17) write `net=process` and
`net=top`.

**Stack lines** follow the header, indented four spaces:

- PHP frames are rendered `    at Class->method (repo/relative.php:line)` (`::` for a static call);
  frames under `vendor/` and `app/Machine/ErrorFile/` (except its `Canary/`) are dropped; if nothing would remain, the first
  three frames are kept anyway;
- Node frames are V8's, with `node_modules`, `node:internal` and the library's own frames dropped;
- absolute paths are shortened to repo-relative — in Node, every path under `cli/code/`,
  `cli/ffx.mjs` (the self-building shim, the outermost frame of every `ffx` stack), `mcp/src/`,
  `mcp/dist/` and `errorfile/` (`REPO_PREFIX`, §5.2);
- a trace frame's `args` are **never** read, and PHP's `getTraceAsString()` is never called, because
  `zend.exception_ignore_args` is off on this machine and args carry ledger values.

**The control-character guard.** Every field goes through `stripControlChars`: `\x00`–`\x1f`,
`\x7f`, U+2028 and U+2029 become a space. PHP calls `mb_scrub()` first. A message such as
`"x\n[2026-09-21T00:00:00.000Z] [ERROR] [php-web] forged"` stays one physical line and cannot forge a
second header.

**The caps.**

- The message is capped at 2,000 characters, cut in the middle so the start and the end both
  survive.
- The data block is capped at 1,000 characters.
- The whole record is capped at **8,000 UTF-8 bytes** (not characters: after `mb_scrub()` a
  character can be up to four bytes), **cut only at a stack-frame boundary** — PHP measures with
  `strlen()` and cuts with `mb_strcut()`, Node with `Buffer.byteLength()`. If the header line alone
  would pass 8,000 bytes, it is shrunk in this order, identically in `LineFormat::record()` and
  `format.ts`: the message is middle-cut down to a floor of 200 characters; then the cause chain is
  cut (down to nothing); then the message (down to nothing); last, the header itself is
  `mb_strcut()` to fit. Cutting the message alone cannot always make it fit — five causes of 2,000
  characters at up to four bytes each are 40 KB — and the floor keeps the headline readable. Each cut
  length is computed from the **byte** overage applied to a character count, so with multi-byte text
  a step can remove more than strictly needed (a multi-byte header may lose its whole error text);
  the record still fits. A record therefore always fits one `write()` of at most 8 KiB and never
  ends in half a frame or half a character.
- PHP applies the caps **before** it concatenates, so an out-of-memory fatal never allocates a large
  string.

A field with no content is omitted together with its separator. A record ends with `\n`.

### 3.3 `app` values

The `app` column says which **surface** broke. That is the operator's first question, and
`grep '\[php-machine\]'` answers it without any knowledge of routes.

| `app`         | Process                                                     | Written by       | When                                                                         |
| ------------- | ----------------------------------------------------------- | ---------------- | ---------------------------------------------------------------------------- |
| `php-web`     | the `php -S` child of `php artisan serve`                   | PHP              | a web UI route, `/up`, `/error-report`, or a fault with no route under `cli-server` |
| `php-api`     | same                                                        | PHP              | request path `api/v1*` or `oauth/*`                                           |
| `php-machine` | same                                                        | PHP              | request path `machine/v1` or `machine/v1/*`                                   |
| `php-artisan` | any `php artisan …`                                         | PHP              | `cli` SAPI with no routed request and no open job frame                      |
| `php-queue`   | whichever process dispatched the job (the sync driver)      | PHP              | a job frame is open, or the throwable is in the job-failure map (below)       |
| `ffx`         | the CLI                                                     | Node (vendored)  | always                                                                       |
| `mcp`         | the MCP server                                              | Node (vendored)  | always                                                                       |
| `web`         | a browser tab, any layout, including login and error pages | PHP ingest       | stamped by the server; the client cannot choose it                           |

PHP decides the value at write time, in this order: (1) the throwable being written is in
`RequestState`'s **job-failure map**, or a job frame is open on `RequestState` → `php-queue`;
(2) `PHP_SAPI === 'cli-server'` or a current route exists → by request path, as in the table;
(3) otherwise `php-artisan`. There is no `php-test`: a **routed** PHPUnit request produces the
production value. One difference is accepted and named: a fault with **no matched route** (a throw in
global middleware, a 404 before routing) is `php-web` or `php-api` in production, because the SAPI is
`cli-server`, but `php-artisan` under PHPUnit, where the SAPI is `cli` and no route exists. Tests
that assert `app` therefore use routed probes; no test asserts `app` for a no-route fault.

**Why a job-failure map.** On the sync driver, `SyncQueue::handleException()` fires
`JobExceptionOccurred`, then `Job::fail()` may fire `JobFailed`, and only **then** rethrows to the
dispatcher; `SyncQueue::executeJob()` fires `JobAttempted` in its `finally`. The job frame is
therefore already popped when `MachineExceptionHandler::report()` sees the throwable. So the
`JobExceptionOccurred` listener (and `JobFailed`, when it fires) records the event's exception in a
`WeakMap<Throwable, {job, during}>` on `RequestState`, and `Context::app()`/`Context::doing()`
consult it: a throwable found there is written as `php-queue`, `running job {ClassBasename}`, with
the dispatcher's `doing` in `data.during`, even after the frame is gone. `JobFailed` is **not**
guaranteed: `Job::fail()` returns before its `try/finally` when the job is already deleted, and a
throwing rollback skips it, so `JobExceptionOccurred` is the map's primary source.

`php-queue` is expected to be rare. `QUEUE_CONNECTION` defaults to `sync`, no `queue:work` runs on
this machine, and a sync job's exception bubbles to whoever dispatched it. The value exists so that a
failed job is still visible as a job. Only a job that really goes through `dispatch()` fires the
`Job*` events: a job that code calls through `->handle()` directly — as the cron does with
`DownloadExchangeRates` (`ExchangeRatesCronjob.php:85-88`) — fires none, and its fault is written as
`php-artisan` (or `php-web`) under the caller's `doing`.

### 3.5 The fold-state sidecar — `error.fold`

PHP's web requests are separate, short-lived processes, so a burst fold that lives in memory forgets
everything between requests. The sidecar is the shared memory. It is JSON:

```json
{"v":1,
 "k":{"<key>":{"f":1790016062118,"s":1790016071004,"n":37,"l":"ERROR","a":"php-machine",
              "W":"app/Machine/Ingest/Importer.php","d":"importing a statement row",
              "h":"RuntimeException: Synthetic row failure"}},
 "b":{"w":1790016060000,"n":412,"x":0},
 "r":{"w":1790016060000,"g":38,"x":0,"c":{"k3x9q2ab":38}}}
```

| Part | Holds                                                                                                  |
| ---- | ------------------------------------------------------------------------------------------------------ |
| `v`  | the format version; anything but `1` is treated as corrupt                                            |
| `k`  | one entry per open fold key: first seen `f`, last seen `s`, owed count `n`, level, app, where, doing, headline |
| `b`  | the file budget slot: window start, records written, records dropped (§4.7)                            |
| `r`  | the ingest rate slot: window start, global count, dropped events `x` (rate **and** event-cap drops), per-`sid` counts (§4.10) |

- **Key:** `xxh128(app␁where␁doing␁FQCN␁Normalizer::message(msg))`. The normaliser turns UUIDs into
  `<uuid>`, hex runs of 8 or more into `<hex>`, absolute paths into `<path>`, digits into `#`, and
  cuts to 300 characters. The stack is never part of the key.
- **What an entry stores is capped.** `h` (the headline) is cut to at most 200 characters — the
  summary line needs only a short headline — and `W` and `d` to at most 200 each. The file is written
  with `json_encode(…, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES)`, so non-ASCII text is not
  inflated to six-byte `\uXXXX` escapes. A full sidecar of 1,000 keys is therefore well under 1 MiB.
- **Caps:** at most 1,000 keys and 1 MiB. Past 1,000, the least-recently-seen key is evicted, and an
  evicted key that still owes a count gets its summary line first. The **writer** also enforces the
  byte cap: before it rewrites the file (§4.7 step 8), if the serialised state is 1 MiB or more, it
  evicts LRU keys — queueing each one's owed summary — until it is under 1 MiB. So a file the reader
  finds over 1 MiB can only mean real corruption.
- **Lazy summaries:** the next write from **any** process sweeps every closed window and writes its
  summary. `ffx logs --errors` also reads the sidecar and prints `owed: ×N <where> <doing>` for every
  open key, so the reader never misses a count that nobody has flushed yet. It reads **without
  locking** and never writes. PHP rewrites the sidecar in place, so an unlocked read can see an empty
  or half-written file: on empty or invalid JSON, `ffx` prints `owed counts unavailable` and carries
  on; it never retries in a loop and never repairs the file.
- **Recovery:** bad JSON, a wrong `v`, a file over 1 MiB (which the writer never produces) or bad
  field types reset the sidecar, and
  **one** WARN is queued: `the fold state was unreadable and was reset`. A clock that went backwards
  closes the window.
- **The sidecar's own WARN lines.** They are written under the writer's own `app` with the library
  file as `where`:
  `[WARN] [<writer app>] [app/Machine/ErrorFile/FoldState.php] reading the fold state — the fold state was unreadable and was reset {pid=…}`
  and `[WARN] [<writer app>] [app/Machine/ErrorFile/FoldState.php] enforcing the file budget — dropped N records over the file budget of 600/min {pid=…}`.
  The ingest drop WARN is the §3.4 golden
  (`[WARN] [php-web] [app/Machine/ErrorFile/Ingest.php] receiving browser error reports — … {via=php-web pid=…}`).
- **One file, one lock order.** The budget and rate slots live in the same file, so there is one
  lock and one lock order: always `error.fold` before `error.err`. Node never locks or writes
  `error.fold` (its only access is `ffx logs --errors`'s unlocked read), so no deadlock is possible.
- **Creation and failure.** `FoldState` calls the shared `Paths::ensureDir()` — `umask(0o077)` saved
  and restored around a lazy `mkdir(dirname, 0o700, true)` — **before** `fopen(…, 'c+')`, so the
  sidecar is created `0600` even when it is the first file in a fresh `~/T/firefly/`. Any open
  **or** lock failure on `error.fold` falls through to the unfolded write (§4.7 step 7); the record
  is never lost to a sidecar problem.
- **Privacy:** the sidecar holds headlines, which pass through the same redaction as the line
  (§12). The redaction test asserts its needles are absent from `error.fold` too. It never stores a
  raw client string as a key: a browser `sid` is validated first (§4.10 guard 6).

### 4.3 Core behaviour — the one pipeline

Every PHP record, whatever produced it, goes through `Reporter`. Its internal entry points are:

Each returns a status — `written`, `folded`, `dropped`, `unfolded`, `seen`, `skipped` or `failed` —

§3.2 context-key order; `$original` is the thrown `MachineException`, for the job-failure-map lookup.
`Reporter::lastAdmitted()` tells the log listener the fold key of the record it just admitted (the
storm fast path, §4.6). Keeping `handlerReport()`'s logic in `Reporter` keeps `ErrorFile.php` a thin

0. **FATAL first aid.** For a `FatalError` whose message starts `Allowed memory size`, the memory

   `Site::fatal()` call; a second raise is harmless.
1. **Busy gate.** If `Reporter::$busy` is set, return. This stops any fault inside the library from

3. **Seen.** For a throwable: already in `Reporter::$seen` (a `WeakMap<Throwable, true>`) → return;

6. **Redact.** `Redactor::text()` on error and causes, `Redactor::data()` on data (§12).

8. **Fold.** `Folder::admit($path, $record)` runs the whole non-FATAL algorithm — L1, `FoldState`

### 4.4 The writer — `Appender`

`Appender::append(string $path, string $bytes): bool` is the only code that opens `error.err`:

1. `$old = umask(0o077); try { … steps 2–6 … } finally { umask($old); }` — the umask is **always
   restored**, as `Audit.php:103-109` does, so files upstream creates later in the same request or
   artisan command (the daily log, cache, sessions, uploads, exports) keep their usual modes.
   `FoldState` uses the same save-and-restore through `Paths::ensureDir()`.
2. `@fopen($path, 'ab')`. Only on the first failure, `Paths::ensureDir()` (`mkdir(dirname, 0o700,
   true)`) and retry.
3. `flock(LOCK_EX | LOCK_NB)`, spinning in 5 ms steps for at most **200 ms**.
4. Inode check: compare `fstat` against `stat($path)`. If another process rotated the file, reopen,
   up to three times.
5. Real-size check after `clearstatcache()`. At 5 MiB or more, rotate **under the lock**: unlink
   `.5`, rename `.4 → .5` … `error.err → .1`, reopen.
6. One `fwrite`, `fflush`, unlock.

If the lock times out, the bytes are written unlocked with `O_APPEND`, in `fwrite` calls of **at most
8 KiB** each, every call holding one or more whole records (a record is at most 8,000 bytes, §3.2).
A queued batch — summaries from a sweep of up to 1,000 keys, recovery WARNs, then the record — is
therefore never one large unlocked write, and on a local filesystem the kernel lands each call at the
end of the file in one piece. A lock is an ordering nicety; it must never let one stuck writer, such as a paused debugger,
freeze every faulting web request. The timeout is **sticky per lock file** (`Appender::lockBounded()`):
after one 200 ms timeout on `error.err` or `error.fold`, every later attempt on that file in the same
process makes one non-blocking try and no spin, until a try succeeds or one fold window (60 s) passes.
A held lock therefore costs a request 200 ms **once**, however many records it writes (AC 6). On the
first failure in a process, the appender writes **once** to `php://stderr` and then stays silent.

Several processes may append at once: the web process, any number of `php artisan …`, PHPUnit
sandboxes, `ffx` and `mcp`. PHP writers serialise on `flock`. Node writers do not lock; they rely on
`O_APPEND` with one write per batch, and on a real-size check before rolling (§5.5). A PHP writer and
a Node writer can both roll in a race. That shifts history by one generation; it never tears a line.
So every step of the Node roll is tolerant on its own (a generation that vanished or will not move
is skipped), the only file a roll ever removes is `.N`, and a failed `error.err → .1` rename re-reads
the real size and keeps appending — a roll never deletes the active file.

### 4.5 The handler net — tier T1

```php
{

        @ini_set('memory_limit', (string) (memory_get_usage(true) + 16 * 1048576));   // FIRST (§4.7)
    }
    ErrorFile::handlerReport($e, $this);   // total; writes BEFORE parent::report()

        return;
    }
    parent::report($e);
}
```

`handlerReport()` never throws, so it needs no try block at the call site. Inside, in this order:

0. **Fill the written-set, before any early return** (but after the memory raise above, which is
   `report()`'s own first statement). `Normalizer::message($e->getMessage())` is
   added to `RequestState`'s written-message set for **every** throwable `handlerReport()` sees —
   written, declined by `shouldReport()`, an answer-coded `MachineException`, folded or dropped by
   the budget. `Handler::render()` writes a bare `Log::error($e->getMessage())` at `Handler.php:216`
   for every web (non-JSON) exception without a Firefly treatment, including ones `$dontReport`
   declines: `AuthenticationException` (`The user is not logged in but must be.` on every logged-out
   visit), `TokenMismatchException` (419), a web-form `ValidationException`, `HttpException` and
   `PostTooLargeException`, `ModelNotFoundException`, and the 503 maintenance answer. Without this
   step each of those would surface as a T3 WARN; with it, the listener drops the echo at §4.6
   step 7 (R7).
1. **A `MachineException` whose code is `internal` or `upstream_error` is unwrapped.**
   `Classifier::unwrap()` walks `getPrevious()` through the `MachineException` wrappers and returns
   the **first** non-Machine throwable it reaches (whose own previous chain is still printed as
   ` | cause:`), else keeps the `MachineException` itself; the walk is cycle-safe and stops at depth
   16. The first, not the deepest: taking the deepest would drop the headline of the real fault (a
   `RuntimeException` wrapping a `PDOException` would print only the `PDOException`). It is written at ERROR with
   `code=` and `status=` in data. **Exception — the batch echo of a fault already admitted.** The
   skip is keyed on the exact event, never on "some record was written for this `rid`":
   - `MirrorController::dispatchInternal()` brackets `$router->dispatch($sub)` with
     `RequestState::enterNested()` and `leaveNested()` in its existing `try/finally`.
     `enterNested()` bumps the nested depth and hands out a fresh dispatch **token**.
   - When `handlerReport()` **admits** a T1 ERROR or FATAL record while the nested depth is above 0,
     it adds the current token to `RequestState`'s covered-dispatch set. Admitted means written,
     L1- or L2-folded, **or** dropped by the budget: the fault is accounted for in every case. A
     log-net record (T2, T3, T4) never covers a dispatch.
   - `BatchController::runOperation()`, on the envelope-error path (`:307`) only, and only when the
     envelope code is `internal` or `upstream_error` and `RequestState::lastDispatchCovered()` is
     true, calls `ErrorFile::markEcho($e)` on the cause-less `failed(…)` exception before throwing
     it. `markEcho()` puts it in `RequestState`'s echo `WeakMap`.
   - `handlerReport()` skips a cause-less `internal`/`upstream_error` `MachineException` **only**
     when it is in the echo map.

   So the batch case writes exactly one `[php-machine]` line per internal op fault: the op's real
   throwable was reported by the sub-request's routing pipeline (`dispatchInternal()` →
   `$router->dispatch()` → `report()`), and its echo is marked. Every other cause-less internal is
   written: `BatchController.php:310` (`'The operation did not report a write.'`),

   record, and it must be written). A T3 WARN earlier in the same request never suppresses a later
   ERROR.
2. **Any other `MachineException` writes nothing** (R7).
3. **`$handler->shouldReport($e)` is true, or `$e` is an `HttpExceptionInterface` with status ≥ 500
   and ≠ 503** → write. A `Symfony\Component\ErrorHandler\Error\FatalError` is written as FATAL with
   `net=shutdown` (§4.7); everything else as ERROR with `net=report`. Note that upstream does not list
   `DuplicateTransactionException` in `$dontReport`, so an **uncaught** one is written, although the
   plane renders it as a `conflict` answer. Plane code catches it today (`TransactionController`,
   `Importer`), so only an escaped one reaches the file; if that proves noisy, a plane request whose
   throwable `Envelope::fromThrowable()` maps to an answer code could be treated as an answer (not
   implemented).

Why this design:

- **Write first.** The write happens before `parent::report()`, so it survives a `MailError` job that
  throws and an `APP_LOG_LEVEL` above error.
- **Honour `dontReport` without copying it.** `shouldReport()` is upstream's own decision, so
  `AuthenticationException`, `ValidationException`, `NotFoundHttpException` and the rest stay silent.
- **The ≥ 500 override.** Upstream lists every `HttpException` in `$dontReport`, so an `abort(500)`
  would otherwise be invisible. 503 is excluded because it is the maintenance-mode answer.

**The storm fast path.** A T3 line repeated from the same call site in the same request state must
not pay the full pipeline each time (AC 5). The listener keeps a per-listener memo
`level + message → where → [path, fold key, request-state fingerprint]`, learning the fold key from
`Reporter::lastAdmitted()`, and remembers the backtrace depth at which the call site was found. A
repeat takes one limited `debug_backtrace` plus one frame compare instead of the depth-30 walk, and,
when the site and state match, goes straight to `Folder::bump()` — L1 `n++`, zero I/O. `Folder`
caches each L1 slot's fold window, so `bump()` does no config lookup. Measured: about 24 ms added
for 10,000 identical `Log::error` calls in one request.

(`Could not find currency with code "…"`) and sometimes a chatty answer that upstream logged at the
wrong level. WARN says "worth a look" without claiming "broke". The replay gate (§16.2) is how the
tiering is shown to keep a normal day at 10 lines or fewer; its first run and the decision taken on
it are recorded in §16.2.

### 4.7 Folding, the budget and FATAL

**Two fold layers.** Deduplication by object (R4) is not enough: an upstream loop can log the same
line ten thousand times in one request, and fifty separate requests can each fault once.

- **L1 — in process.** A static table keyed by `path + fold key`, at most **200** keys, a 60 s
  window. A repeat inside the window is `n++` with **zero I/O**. In `php -S` statics reset per
  request, so L1 is naturally per request; in a long artisan command it spans the command.
- **L2 — the sidecar.** L1 sends only the **first** sight of a key to L2. On the first owed count, L1
  registers **one** `register_shutdown_function` flush, guarded by a static, that moves the owed
  counts into L2 under one lock. The flush skips a path whose directory has gone, which covers
  PHPUnit sandboxes.

Each L1 entry remembers the L2 window it was admitted into: the `f` that `FoldState::admit()`
returned for the key (another process may have opened that window first), plus its own owed count.

For one non-FATAL record, the full algorithm is:

1. L1: if the key was seen in this process and its window (from the remembered `f`) is still open,
   `n++` and return. If the key is in L1 but its window has **closed** — a long artisan command, a
   long ingest request — this sighting is a **rollover**: the old window's owed count travels with
   the new first sighting into steps 2–8, in the **same** locked transaction, and step 4 hands it to
   L2 before anything is swept or admitted. When L1 is full, evict the oldest key and hand its owed
   count to the shutdown flush.
2. `Paths::ensureDir()`, then open `error.fold` (`c+`) and take a bounded `LOCK_EX` (200 ms). On
   **any** open failure or lock timeout, skip to step 7 without folding: the record may be
   duplicated, but it is never lost. The key is still remembered in L1 with `f = now`, so its
   repeats in this process are `n++` with zero I/O and their count goes to the shutdown flush
   (one summary line), instead of one lock attempt and one line per repeat.
3. Load. Reset on corruption and queue one WARN (§3.5).
4. **Hand over, then sweep.** A rollover's owed count goes first: if L2's entry for the key still has
   the same `f`, add the count to its `n`, so the sweep summarises the old window with its full
   count; if that window was already swept or evicted by another process, queue the summary line
   for the old window directly (`×N more in the 60s window from <old f>`). Then sweep every closed
   window, and any clock rollback, into queued summary lines.
5. **Admit.** A key inside its window → `n++`, `s = now`, and **nothing** is appended for it. A new
   key → insert and queue the record. Past 1,000 keys, evict by LRU and queue a summary for any owed
   count.
6. **Budget.** At most **600** PHP lines per 60 s window across all PHP writers, charged **only** for
   lines that step 7 will actually append (new-key records, summaries, recovery WARNs) — never for an
   `n++` on an open key, so a storm of one fault folds into its summary instead of being counted as
   dropped. At 600, a new-key record is counted as dropped and nothing is written for it; when a
   window with drops closes, queue one WARN: `dropped N records over the file budget of 600/min`.
   Every queued line — summaries and WARNs — is charged to the budget but **never** dropped; only a
   new-key record can be. A dropped key is not inserted into L2, so a later sighting is counted
   afresh and is never summarised as if it had been written.
   Without a budget, a runaway that emits distinct messages would rotate all 25 MiB of history away
   within minutes.
7. `Appender::append()` writes every queued line in **one** call (split into ≤ 8 KiB writes only on
   its unlocked fallback, §4.4).
8. Enforce the sidecar's byte cap (§3.5: evict LRU, queueing owed summaries, until under 1 MiB),
   rewrite the sidecar in place (`ftruncate`, `rewind`, one `fwrite`, `fflush`), then unlock.

A crash between steps 7 and 8 loses at most one count, or repeats one line.

**The shutdown flush.** It takes the fold lock once (`error.fold` before `error.err`, the one lock
order) and, for each L1 owed count: if L2 has an open entry for the key with the **same** `f`, it
adds the count there; otherwise — the window was swept by another process, the key was evicted, or
L2 now holds a newer window — it queues the summary line for the L1 window itself
(`×N more in the 60s window from <that f>`) and appends it through `Appender`. It never opens a new
L2 window for an owed count, so a count is never attributed to a window it did not happen in.

**FATAL.** A FATAL skips L1, L2, the budget and JSON, and appends straight through `Appender`
(step 7 only). If the message starts `Allowed memory size`, the **first statement of
`MachineExceptionHandler::report()`** — a class that is already loaded, because it is the bound
handler — calls `@ini_set('memory_limit', (string) (memory_get_usage(true) + 16 * 1048576))`. That

### 4.8 Context — `app`, `doing`, `where` and `rid`

**`doing` for a net record.**

- **HTTP:** `handling {METHOD} /{route uri template}`, with the route **name** in `data.route`. For
  example `handling GET /api/v1/accounts/{account}` with `route=api.v1.accounts.show`, or
  `handling POST /machine/v1/transactions`. When no route matched, it is
  `handling {METHOD} (no route)`. The raw path is **never** used, because a path can carry a ledger
  value (`/tags/show/<name>`); a template never does.
- **Artisan:** `running artisan {command}`, in this order: the top of the `CommandStarting` stack;
  then `RequestState::lastFailedCommand`; then `$_SERVER['argv'][1]`, used only if it matches
  `^[a-z0-9:_-]+$`. The stack serves the **log-net** records a command emits while it runs. It
  cannot serve a command's own uncaught exception: Symfony's `Application::doRunCommand()` fires
  `ConsoleEvents::TERMINATE` — which Laravel reroutes to `CommandFinished` — **before** it rethrows,
  so the frame is already popped when `Kernel::handle()`'s catch reaches `report()`. So the
  `CommandFinished` listener, when the exit code is non-zero, keeps the popped name as
  `lastFailedCommand`, and a T1 record reads it before the argv fallback. That also gives the right
  `doing` under PHPUnit's `$this->artisan()`, where `argv` belongs to PHPUnit and the fallback would
  say `running the app`. A known wrinkle of the argv regex: under
  `phpunit -c phpunit.machine.xml`, `argv[1]` is `-c`, which matches, so an **unrouted** record written
  during a test run reads `running artisan -c`. No test asserts `doing` for such a record; requiring a
  leading `[a-z0-9]` would close it.
- **A job:** `running job {ClassBasename}`, with the dispatcher's `doing` in `data.during`.
- **Anything else:** `running the app`.

**`where` for a record.** An explicit site uses the literal passed to `ErrorFile::for()`, with no
line number (R14). A net record uses the **origin** as `path:line`: for a throwable,
`getFile():getLine()` when that file is in the repo and not under `vendor/`, otherwise the first trace
frame that is; for a bare log line, the first backtrace frame outside `vendor/` and outside the
library (§4.6 step 8). Naming `MachineExceptionHandler.php` would tell the reader nothing.

**Context keys.** `Context::base()` supplies, where known: `route` (the route name), `status` (for
an HTTP exception or an unwrapped `MachineException`), `code` (the plane code), `caller` (from
`X-Firefly-Client`, read by `Context.php` itself and kept only when it matches `[a-z0-9_.-]{1,32}`,
the same validation `Audit::caller()` applies; `Audit::caller()` is not called, because its header
read sits outside the directory `SourceCanaryTest` fences, R12), `rid`, `took_ms` (from
`Clock::elapsedMs()`), `during` (for a job) and `pid`. `caller`, `rid` and `took_ms` are known only
for an HTTP record, and a FATAL gets no `took_ms` (§3.2).

**The correlation id.** `ffx` and `mcp` mint 8 hex characters per plane call and send them as
`X-Firefly-Request-Id`. PHP adopts the header when it matches `^[0-9a-f]{8,16}$`, and otherwise mints
one lazily, **only when a record is written**. `CliError` and `ToolError` gain an optional `rid`
property that is never serialised into an envelope, so the client-side record carries the same
`rid=`. The 8–16 range keeps the id below the ≥ 32-hex key scrub. The id is not echoed in a response
header, so the apis.mdx wire contract does not change. The rid lives on `RequestState`, taken from
the **outer** request, so a batch op's sub-request record (§4.5) carries the batch call's `rid`.
The header read is one of the two named header reads R12 allows in `Context.php`.

In the MCP the plane-failure `ToolError` is built in `server.ts` `#planeFailure()` from a
**returned** envelope, not in `client.ts`. So `PlaneEnvelope` carries an optional, client-side
`rid` that `PlaneClient.call()` sets (overwriting any wire value), `#planeFailure()` copies it onto
the `ToolError`, and a `ToolError` that `call()` throws gets it there. The server builds its own
reply envelope, so the rid never reaches the model.

### 4.10 The ingest route and its gate

`routes/error-report.php` is a fork-owned file in upstream's `routes/` directory:

```php
Route::any('error-report', ErrorReportController::class)
    ->middleware([ErrorReportGate::class])
    ->name('fork.error-report');
```

It sits **outside** `/machine/v1` and outside the `web` and `api` groups, so it has no session, no
cookies, no CSRF and no auth. It must not: the login page and the error pages have no session, and
the machine key must never reach a browser. `Route::any` lets the method guard answer `204` instead
of Laravel's 405. The machine plane cannot host it: its `OriginGate` refuses every browser by design
(apis.mdx §4.7).

The body is:

```json
{ "sid": "k3x9q2ab",
  "events": [ { "ts": "2026-09-21T18:46:13.270Z", "level": "ERROR", "where": "/transactions/create",
                "doing": "calling POST api/v1/transactions",
                "error": "AxiosError: Request failed with status code 500 (code=ERR_BAD_RESPONSE)",
                "cause": "", "stack": "at build/assets/create-Bq3xT9aa.js:1:2044",
                "data": { "status": 500, "net": "axios" } } ] }
```

`cause`, when there is one, is sent in the Actual Budget `ErrorRecord` form: the whole chain **with**
its leading separators, `" | cause: RangeError: … | cause: Error: … (code=E_SYNTH)"`, at most 5
links, capped at 2,000 characters. Ingest writes it as is and never prefixes another ` | cause: `.
`stack` is unindented `at …` lines joined by `\n`, at most 12 frames × 400 characters; the server
indents them. `errorfile/fixtures/browser-batch.json` is the reference.

**Guards, in order.** Every refusal is a `204` with an empty body and `Cache-Control: no-store`, and
nothing is written. Nothing about the route is probe-able.

1. **Loopback.** `REMOTE_ADDR` ∈ `LoopbackGate::LOOPBACK`. The constant is reused, and
   `TrustProxies` is ignored, exactly as the plane does.
2. **Same origin.** `Host` passes `OriginGate::isAllowedHost()` (which reads the request's own
   `Host` header). `Sec-Fetch-Site`, when present, must be `same-origin`. `Origin` must be one of:
   - **absent**;
   - the literal **`null`**, accepted **only** together with `Sec-Fetch-Site: same-origin`;
   - a serialised origin that passes the new helper **`ErrorReportGate::isSameOrigin(string $origin,
     Request $request)`**, because `isAllowedHost()` takes a `Request`, not a string, and compares the
     host name only. `isSameOrigin()` parses `scheme://host[:port]`, requires the scheme `http`,
     requires the host to be in `config('machine.allowed_hosts')`, and requires the whole
     `scheme://host:port` (default port filled in) to **equal** the request's own
     `getSchemeAndHttpHost()` — same origin, not merely an allowed host name on another port.

   Which one arrives depends on the transport. Every Firefly response carries
   `Referrer-Policy: no-referrer` (`SecureHeaders.php:123`, `:133`). Under the Fetch spec the
   no-referrer `null` substitution applies only to a request whose mode is **not** `cors`:
   - the keepalive **`fetch`** — the normal 2-second delivery — runs in the default `cors` mode, so a
     same-origin POST carries the **real** origin (`Origin: http://127.0.0.1:7373`) with
     `Sec-Fetch-Site: same-origin`, and passes through `isSameOrigin()`;
   - **`sendBeacon`** with a `text/plain` Blob (a CORS-safelisted type, so `no-cors` mode) —
     used on `pagehide` and hidden — carries `Origin: null` with `Sec-Fetch-Site: same-origin`.

   A guard that accepted only one of the two would refuse half the browser's reports. Without this
   guard, any website open in the operator's browser could send a CORS-simple `text/plain` beacon to
   `127.0.0.1:7373/error-report`; the request would arrive from a loopback address, pass guard 1, and
   fill or rotate the forensic history. A cross-site beacon carries `Sec-Fetch-Site: cross-site`, so
   its `Origin: null` is refused; another localhost app's fetch (`Origin: http://localhost:8000`)
   fails `isSameOrigin()` on the port even when `Sec-Fetch-Site` is missing. The Host check also
   blocks DNS rebinding.
3. **Method.** `POST`.
4. **Content type.** Starts with `text/plain` or `application/json` (D7). Both browser transports
   send `text/plain` (§6.5), so Laravel's `isJson()` is false and upstream's global
   `TrimStrings`/`ConvertEmptyStringsToNull` middleware (`bootstrap/app.php:86-87`, which runs before
   any route middleware and calls `$request->json()` → `getContent()` + `json_decode` on a JSON body)
   never parses our body. An `application/json` body, which our module never sends, is still
   accepted, but it is stated plainly: upstream's global middleware has **already** read and decoded
   it, bounded only by `post_max_size`, before this gate runs. The size and depth guards below bound
   what the gate reads, not what that middleware read.
5. **Size.** `Content-Length` present, numeric and ≤ 65,536; a missing or non-numeric
   `Content-Length` also refuses (fail closed — both browser transports always send it; a
   non-numeric value is in practice answered 413 by upstream's `ValidatePostSize` before the gate).
   The body is read from `php://input` with a cap of 65,537 bytes, in `Ingest.php` only;
   `getContent()` is never called by the library.
6. **Parse, `sid` and events.** `json_decode(depth: 8, JSON_THROW_ON_ERROR)` inside a try; `events`
   must be an array; the first 50 are kept, and the rest are **event-cap drops**, added to the rate
   slot's drop count `r.x` in step 7. `sid` must be a string matching `^[a-z0-9]{8}$`; anything else —
   missing, non-string, too long — is replaced by the fixed bucket `_`, and the events are counted
   against it. A raw client string never becomes a key in `error.fold`.
7. **Rate.** Under one `FoldState` lock: 240 events per 60 s per `sid` (at most 200 client entries,
   oldest evicted) and 1,200 per 60 s globally. Rate drops and the step-6 event-cap drops are both
   added to `r.x`, and each rate window with `r.x > 0` produces exactly one WARN, written lazily by
   the first write after the window closes (like a fold summary):
   `dropped N browser reports over the ingest limits`. The key is `sid`, because `REMOTE_ADDR` is
   always loopback, so "per client address" would collapse to one bucket; D7's "per (app, client)"
   is read this way (V11, §16.5). The rate slot is **saved and the
   lock released before step 10**: `flock` is per open-file description, so a second
   `LOCK_EX|LOCK_NB` on `error.fold` from `writeRecord()` in the same process would otherwise spin
   200 ms and fall back unfolded for every event. If the `FoldState` lock cannot be taken at all, the
   step fails **open**: the at most 50 capped events are accepted, matching §4.7 step 2's "never lost
   to a sidecar problem".
8. **Sanitise and re-redact.** `where` and `doing` validated by the closed rules below; field caps
   (where and doing 200, error and cause 2,000, stack 24 lines × 400 characters — a looser backstop
   than the browser's own 12 frames, §6.4); `level` ∈ {WARN, ERROR}, where FATAL becomes ERROR,
   EXPECTED is dropped, and any other or missing `level` is written as ERROR; an event that is not a
   JSON object is skipped; a non-empty `cause` that does not start with ` | cause: ` gets that
   separator prefixed, so the §3.2 convention (the cause carries its own separators) holds; `ts` is
   kept only if it is ISO-8601 with `Z`, otherwise now; `data` goes through `Redactor::data()`; the
   text scrubs run on every text field (§12). The server never trusts the browser's redaction.
9. **Stamp.** `app = web`, `data.via = php-web`.
10. **Write.** `ErrorFile::writeRecord()`: folded and budgeted, but not deduped by object.

**The server-side rule for `where` and `doing`.** They are checked, not blindly re-templated:
`templatePath()` is a URL-path templater, and applied to a phrase such as `running page script` it
would turn the whole phrase into `{x}`. So:

- **`where`:** if it starts with `/`, it is a page path and is re-templated with `templatePath()`
  (§6.4), so `/tags/show/Synthetic Tag` is written `/tags/show/{x}`. Otherwise it is accepted only if
  it **exactly equals** one entry of a closed allowlist of fork-owned browser module paths — today
  `resources/assets/v3/js/support/error-file-app.js` (§7.3, Pattern 10). Anything else becomes `{x}`.
- **`doing`:** accepted only if it is one of the closed browser phrases — `running page script`,
  `settling a promise`, `evaluating an Alpine expression`, `bootstrapping the page`,
  `sending error reports` (§6.5), and the glue's own literals, today `attaching the jQuery net` — or
  has the form `calling {METHOD} {path}`, where `METHOD` is one of `GET HEAD POST PUT PATCH DELETE
  OPTIONS` and `templatePath()` is applied to the **path part only** (`calling POST
  api/v1/transactions` survives unchanged; `calling GET api/v1/tags/groceries` becomes
  `calling GET api/v1/tags/{x}`). Anything else becomes `{x}`.

Both allowlists are constants in `Ingest.php`. A new fork-owned browser module or phrase adds an
entry there, in the same commit. `IngestRouteTest` asserts that every `doing` and `where` in
`errorfile/fixtures/browser-batch.json` survives ingest byte for byte, and that a `where` of
`/tags/show/Synthetic Tag` is written `/tags/show/{x}`.

A fault inside the controller is caught by
`ErrorFile::for('app/Machine/ErrorFile/Http/ErrorReportController.php')->caught(…)` and still answers
`204`, writing `[php-web] … receiving browser error reports`. `ErrorReportController::__invoke()` is
the total boundary: `Ingest::accept()` catches only the JSON parse failure and lets every other fault
reach this catch (§4.1). It is never re-reported through the browser. A body above PHP's `post_max_size` is refused by
upstream's global `ValidatePostSize` with a 413 before the gate runs. That is harmless.

**Why this is safe with no secret.** Its safety comes from the guards: loopback only, same origin
only, write-only, append-only, capped, sanitised, rate-limited, and it produces no output. A process
on this machine that can post to it could already write to the file directly.

### 5.5 The node sink — `node.ts` and `rolling-file-writer.ts`

`installNodeErrorFile(opts)` resolves the path, creates the `RollingFileWriter`, sets the sink,
drains the pre-install queue and, when `handleProcessErrors` is true (the default), installs, idempotently:

- `uncaughtExceptionMonitor` → `fatal`, `net=process`. The monitor observes without changing Node's
  own crash behaviour.
- `unhandledRejection` → `fatal` then rethrow when `crashOnUnhandledRejection` is set and this is the
  only listener; otherwise `caught`. Both use `net=process`.
- `beforeExit` and `exit` → a synchronous flush.
- `SIGINT` and `SIGTERM` → a synchronous flush. Then, **only if ours is the only listener** for that
  signal (`process.listenerCount(signal) === 1`), ours is removed and the signal is re-raised;
  otherwise exit is left to the host's own handler. This is AB's rule (`node.ts:119-127`). An
  unconditional re-raise would re-enter every listener: the MCP registers its own SIGINT/SIGTERM
  shutdown (`mcp/src/index.ts:87-89`) and would loop during its async `server.close()`, and
  `ffx logs --follow` (`process.once('SIGINT')`, `orientation.ts:386`) would be killed by the
  signal instead of exiting through its handler. The host's handlers are never replaced.

`RollingFileWriter` is AB's, from the Internal Web App:

- `write(line)` pushes onto an array. **It does no filesystem work.**
- One unref'd 5 ms timer drains the buffer with one async `fs.appendFile` per batch.
- A buffer over 256 KiB forces a synchronous drain, to bound memory in a storm.
- `flush()` is the synchronous barrier used by `fatal`, exit and signals.
- The size is cached. Before rolling at 5 MiB it checks the real on-disk size; a process that finds
  the file already rolled resets its cache and does not roll again.
- Files are created with mode `0600` inside a `0700` directory.
- A write failure falls back to one `process.stderr.write`; the next write retries `mkdir`.

Node never locks or writes `error.fold`: the in-memory folder of a long-lived CLI or MCP process is
enough. Its only access is `ffx logs --errors`'s unlocked, tolerant read (§3.5).

**In-process tests.** `sandbox().env` reaches only spawned children. A test that runs a runtime in
process — the MCP `host()` tests (`calls.test.ts`), the CLI `unit.test.ts` — never imports
`error-file-install.ts`, and `test-sink.ts` is not vendored, so its records would sit in the
pre-install queue. Such a test calls, in `before()`,
`installNodeErrorFile({ app, where, file: path.join(sb.dir, 'error.err'), handleProcessErrors: false })`
and, in `after()`, `resetNodeErrorFileForTests()`, then asserts on the bytes in `sb.dir`.
`resetNodeErrorFileForTests()` flushes, removes the process listeners the install added, forgets the
install **and** resets the core state (sink, pre-install queue, folds, the reported `WeakSet`), so a
stale fold or reported-set from one suite can never silently swallow the next suite's records. Calling
`installNodeErrorFile` **without** `file` anywhere under `cli/code/test/` or `mcp/test/` is
forbidden (it would resolve `process.env` and could reach the real file); a static check in both
suites' canary tests greps for it.

```ts
export type NodeErrorFileOptions = {
  app: 'ffx' | 'mcp';
  where: string;                       // `where` for process-level records
  file?: string;                       // default resolveErrorFilePath(process.env)
  echo?: boolean;                      // default FIREFLY_ERROR_FILE_ECHO === '1'
  crashOnUnhandledRejection?: boolean; // default true (ffx keeps Node's crash)
  handleProcessErrors?: boolean;       // default true
};
export function installNodeErrorFile(opts: NodeErrorFileOptions): { flush: () => void; file: string };
```

Handles: buffering, appending, flushing and rotating the Node side of the file.

### 5.7 How `ffx` and `mcp` classify, and what `ffx` adds

**`ffx`, in `main.ts` `reportError()`.**

- A non-`CliError` → `caught('running an ffx verb', err, { verb, exit: 1 })`.
- A `CliError` whose `code` is `internal` or `upstream_error` → `caught(…, { verb, exit, code, rid })`.
  The code identifies a server fault; the exit number does not, because a `doctor` FAIL is also
  exit 1.
- Every other `CliError` → `expected('running an ffx verb', err)` (R7).
- `client.ts` `transportError()`: the `ETIMEDOUT` `CliError` gains `cause: err` (the
  `ErrnoException`). Its exit and code are unchanged, so `--json-errors` output is untouched; its
  hint becomes `'raise --timeout. ' + H` (§18.1 H7). `reportError()` checks this **before** the
  "every other `CliError`" rule: a `CliError` whose `cause` is a transient `ErrnoException` →
  `warn('running an ffx verb', err, { verb, exit })`, which the §5.2 transient rule folds to one
  WARN per 10 minutes.
- `client.ts` `parse()`: a non-envelope answer with HTTP status ≥ 500 first writes
  `errors.warn('reading the app answer', undefined, { status })`. The `CliError`'s exit and code are
  unchanged, so `--json-errors` output is untouched.
- `bringup.ts` `failWithLogTail()` → `caught('bringing up the web app', cliError, { exit: 5,
  waited_ms })`. This is the one exit-2–6 `CliError` that **is** a fault (R7's carve-out): the web
  app would not come up. When `reportError()` later sees the same object and calls `expected()`,
  the `WeakSet` makes it a no-op. The `server.log` tail is **never** copied into the record: it may
  hold a password-reset link.
- `index.ts`: `process.exitCode = await main(argv).catch(…)` writes `fatal('starting ffx', err)`,
  because a rejected top-level await is not a reliable `unhandledRejection`, and `loadConfig()`,
  `initLogger()` and `--help` run outside `main()`'s try blocks.
- **The transient check.** `isTransientNetworkError` is exported from `errorfile/src/index.ts` (it
  lives in `core.ts`), and both classifiers — `reportError()` here and `server.ts` below — call it on
  `err.cause` first, before the `internal`/`upstream_error` rule.
- **How `main()` reaches `reportError()`.** `main()`'s two catches call it through a one-line handle,
  `const verbErrors = { report: reportError };` → `verbErrors.report(…)`, so the §13.2 coverage

  one classifier; an `errors.*` call in the catch itself would classify each failure twice (a thrown
  primitive cannot be `WeakSet`-marked, so it would fold to a ×2 summary).
- The top-level handles stamp the net: `cli/code/src/index.ts` and `main.ts` declare
  `errorFileFor('<own path>', { net: 'top' })` (N12, N13), and `mcp/src/index.ts` and `server.ts` do

### 6.3 Noise filters

- **Never reported:** an axios `ERR_CANCELED` or abort — `code === 'ERR_CANCELED'`, or
  `ECONNABORTED` whose message contains `aborted` (axios's XHR `onabort`); an axios **timeout**
  (`ECONNABORTED`, `timeout of …`) is still an ERROR with no status — and a jQuery `statusText` of
  `abort`; HTTP **401, 404, 419, 422, 429**; any failure
  after `pagehide` or while `document.visibilityState === 'hidden'`; `ResizeObserver loop…` with no
  Error object; `Script error.` with no Error object; anything whose stack or filename contains
  `/@vite/client`.
- **ERROR:** HTTP status ≥ 500, and a network error (no response) while the page is visible.
- **WARN:** any other 4xx, and the boot watchdog.

419 is CSRF expiry and 429 is the login lockout; both are answers (R7).

### 6.4 Record fields

- `where`: for a net, a **path template** built from `location.pathname` (no query, no hash) by
  `templatePath()`: leading segments are kept while they are static words (`^[a-z][a-z0-9-]*$`), at
  most **two** of them — or at most **one** after an `api/v1/` prefix, which is always kept, so
  `api/v1/tags/groceries` → `api/v1/tags/{x}` — and **every** other
  segment — not just digit runs — becomes `{x}`. So `/transactions/show/12` →
  `/transactions/show/{x}`, and `/tags/show/Synthetic Tag` and `/tags/show/groceries` both →
  `/tags/show/{x}`: a tag name, account name or any other ledger text in a path never reaches the
  file. Digit replacement alone is not enough, and the §12 scrubs would not catch a plain tag name.
  An explicit fork site uses its repo path, which must be on ingest's closed allowlist (§4.10).
- `doing`: `running page script` (window error); `settling a promise` (rejection);
  `calling {METHOD} {path template}` for axios and ajax, where the template is `templatePath()` of
  the request URL with the leading `/` and the query removed (`calling POST api/v1/transactions`,
  `calling GET api/v1/tags/{x}`); `evaluating an Alpine expression`; `bootstrapping the page`;
  `sending error reports` (the over-budget WARN, §6.5). This is a **closed** list: ingest accepts
  only these phrases, the glue's literals and the `calling {METHOD} {path}` form (§4.10).
- `data`: `status` when there is one; for Alpine, `expression` (capped at 120) and `element_id`.
  **Never** a request or response body, and never an element's text.
- `error` (the headline) for the cases with no ready-made one:
  - over-budget WARN: `dropped N browser reports over the page budget of 30 per 60s`, `data: {}`;
  - jQuery net: `AjaxError: Request failed with status code N`, or `AjaxError: Network Error` for
    status 0;
  - a window `error` event with no Error object: `ErrorEvent: <message>`, with a one-frame stack
    built from `filename:lineno:colno`;
  - the watchdog: `Error: the page did not finish booting`, from a plain object so no library frame
    appears, with `data {net: watchdog}`;
  - a thrown primitive: `Thrown string: …` (and the like for other primitive types).
- `stack` and `cause`: see the wire format under §4.10's body. A stack frame whose location is not a
  `.js` file — an inline script's page URL — is passed through `templatePath()`, so a page path never
  leaks through a frame.
- **Caps, applied in the browser too:** `where` and `doing` 200 characters, `error` and `cause`
  2,000, the stack at most **12 frames** × 400 characters, with bundle URLs cut to
  `build/assets/<chunk>.js:L:C`. Ingest guard 8 caps the stack at 24 lines, a looser backstop; the
  other numbers are the same. The server re-applies every cap and checks `where`/`doing` against its
  closed rules (§4.10); it never trusts the browser.
- The body is `{ "sid": "<8 [a-z0-9]>", "events": [...] }`. `sid` is random per page load and used
  only as the rate key; the server validates it (§4.10 guard 6). Records carry no `app`; the server
  stamps it.
- **Clock and randomness come from the scope.** The core reads the time (`scope.Date.now()`, and
  `new scope.Date(…).toISOString()` for `ts`) and the `sid` random source
  (`scope.crypto.getRandomValues`) from the injected `scope` of
  `installBrowserErrorFile({ endpoint, scope })`, which is `window` in production. The browser-core
  test passes a fake scope with a pinned clock and a fixed random source, so the batch it produces
  is deterministic (§15).
- The endpoint is the relative `"error-report"`, so it resolves against `<base href>` and works when
  Firefly is installed under a sub-path.

### 6.5 Transport and budget

A batch is sent at 20 records or after 2 s, with one timer. The budget is 30 records per 60 s per
page; the excess is counted and sent as one over-budget WARN per flush, with `doing`
`sending error reports` and `where` the page path template. On `pagehide` or hidden, the
queue goes out with `navigator.sendBeacon(endpoint, new Blob([json], { type: "text/plain" }))`;
otherwise with `fetch(endpoint, { method: "POST", keepalive: true, headers: { "content-type":
"text/plain;charset=UTF-8" }, body })`. **Both** transports send `text/plain`, so upstream's global
middleware never parses the body as JSON (§4.10 guard 4). Both are same-origin POSTs with
`Sec-Fetch-Site: same-origin`, but their `Origin` differs under the site's
`Referrer-Policy: no-referrer`: the keepalive `fetch` runs in `cors` mode and sends the **real**
origin (`Origin: http://127.0.0.1:7373`), while `sendBeacon` with a `text/plain` Blob runs in
`no-cors` mode and sends `Origin: null`. Guard 2 accepts both (§4.10). The CSP's
`connect-src 'self'` allows both.

**Batch bytes.** A batch is serialised record by record, and a new batch is started before the JSON
would pass about **60 KiB**, measured in **UTF-8 bytes** (`new TextEncoder().encode(json).byteLength`,
or the Blob's `.size`), never `json.length`, which counts UTF-16 units: `JSON.stringify` does not
escape non-ASCII, so a localized message or an Alpine expression makes the byte length exceed the
string length. The `fetch` keepalive quota, the `sendBeacon` limit and ingest guard 5
(`Content-Length ≤ 65,536` bytes) are all 64 KiB, and the keepalive quota is shared by **all**
in-flight keepalive requests of the document, so the next `fetch` batch is sent only after the
previous one has settled; batches queue behind it. One oversized record must never sink the other
nineteen. With the per-field caps in §6.4, a single record is at most about 11 K characters — under
33 KiB even if every character took three UTF-8 bytes — so it always fits a batch of its own. A delivery failure
produces one `console.warn` per page and is never re-queued or reported (R11). A `WeakSet` dedupes
objects. There is **no** browser-side redaction: the server is the authority and re-redacts
everything (§4.10 guard 8), so there is no third copy of the regexes to keep in sync.

**Budget.** At most **3 KB gzip** added to the bundle a page loads, zero requests when nothing
faults, and zero behaviour change on the happy path. Rolldown places the core in the chunk shared by
**both** boot files (`adminlte.esm-*.js`), not in `_dates`; `_dates` carries only the glue. Measured
(gzip -9, builds before and after): the shared chunk grows 2,846 B and `_dates` 137 B, so a session
page loads 2,983 B more and a blank page 2,846 B. To stay inside it the core keeps its sink state in
plain module variables (mangleable) rather than one object.

### 7.1 PHP

```php
namespace FireflyIII\Machine\ErrorFile;

final class ErrorFile
{
    /** Memoised per $where; stores a string and does no other work (R3). $where is a repo-relative literal. */

    /** Called ONLY from MachineExceptionHandler::report(), before parent::report(). Total. */

    public static function markEcho(MachineException $e): void;
    public static function isReported(\Throwable $e): bool;
    public static function path(): ?string;
    // test seams, used only by tests/Machine/**. The facade only delegates: the state lives in the
    // owning class — Paths::usePath()/resetForTests(), Folder::useClock()/now()/resetForTests(),
    // Appender::useFallback()/stderr()/resetForTests() — so each class is testable on its own and
    // ErrorFile.php stays a thin facade (§4.7). Ingest::useInput() is ingest's own seam (§4.1).
    public static function resetForTests(): void;
    public static function usePath(?string $path): void;   // the ONLY in-process path under PHPUnit (R13)
    public static function useClock(?\Closure $nowMs): void;
    public static function useFallback(?\Closure $stderr): void;
}

final readonly class Site
{
    public function caught(string $doing, \Throwable $e, array $data = []): void;          // ERROR
    public function warn(string $doing, ?\Throwable $e = null, array $data = []): void;    // WARN
    public function expected(string $doing, \Throwable $e): void;                          // nothing; EXPECTED under VERBOSE
    public function rethrow(string $doing, \Throwable $e, array $data = []): never;        // ERROR, then throw $e (same object)
    public function fatal(string $doing, \Throwable $e, array $data = []): void;           // FATAL; bypasses every fold
    /** @template T  @param callable(): T $fn  @param T $fallback  @return T */
    public function tryOr(string $doing, callable $fn, mixed $fallback): mixed;            // ERROR on throw, returns $fallback
}
```

```ts
import { errorFileFor, tryOr, tryOrAsync, reportRejection, guard } from './vendor/error-file/index.js';

export type ErrorFile = {
  readonly where: string;
  caught(doing: string, err: unknown, data?: ErrorData): void;     // ERROR
  warn(doing: string, err?: unknown, data?: ErrorData): void;      // WARN

  fatal(doing: string, err: unknown, data?: ErrorData): void;      // FATAL + synchronous flush
};
export function tryOr<T>(errors: ErrorFile, doing: string, fn: () => T, fallback: T): T;
export function tryOrAsync<T>(errors: ErrorFile, doing: string, fn: () => Promise<T>, fallback: T): Promise<T>;

export function isTransientNetworkError(err: unknown): boolean;                              // §5.7
export function reportRejection(errors: ErrorFile, doing: string, p: unknown): void;
```

explicit site passes one argument and carries no `net`. The §13.2 coverage script accepts both forms.

### 7.4 Side by side, and the rules of use

| Intent                          | PHP                                             | TypeScript                                   | Browser                         |
| ------------------------------- | ----------------------------------------------- | -------------------------------------------- | ------------------------------- |
| The handle                      | `ErrorFile::for('app/Machine/X.php')`           | `const errors = errorFileFor('cli/code/src/x.ts')` | `errorFileFor('…/support/x.js')` |
| Report and continue             | `->caught($doing, $e, $data)`                   | `errors.caught(doing, err, data)`            | `errors.caught(doing, err, data)` |
| Something odd, not broken       | `->warn($doing, $e, $data)`                     | `errors.warn(doing, err, data)`              | `errors.warn(…)`                |
| The failure is part of normal operation | `->expected($doing, $e)`                | `errors.expected(doing, err)`                | `errors.expected(…)`            |
| Report, then throw the same object | `->rethrow($doing, $e)`                      | `errors.rethrow(doing, err)`                 | —                               |
| The process is dying            | `->fatal($doing, $e)`                           | `errors.fatal(doing, err)`                   | —                               |
| A value with a fallback         | `->tryOr($doing, fn () => …, $fallback)`        | `tryOr(errors, doing, () => …, fallback)`    | —                               |
| Fire-and-forget promise         | —                                               | `reportRejection(errors, doing, p)`          | —                               |
| A callback nobody awaits        | —                                               | `guard(errors, doing, fn)`                   | —                               |

- **One handle per file.** PHP: create the handle inside the catch, or declare one
  `private const string WHERE = 'app/Machine/X.php';` per class and use `ErrorFile::for(self::WHERE)`.
  TypeScript: one module constant named `errors` directly after the imports; the coverage script keys
  on names that are `errors` or end in `Errors`.
- **`doing` is a literal gerund phrase** with no trailing period. Dynamic parts go in `data`:
  `->caught('importing a statement row', $e, ['row' => $i])`. A row index is an opaque number, so it
  is allowed. An account **name** is ledger data and is refused (§12).
- **Data values are scalar or null.** The call site never formats, never redacts and never touches
  `$request`.
- **`guard` allocates once**, where the callback is registered. Never call it in a loop.

### 8.3 Pattern 3 — PHP: keep the cause when converting to a plane code

The plane converts a fault into `internal` for the caller. The conversion must hand the original
throwable on, or the handler net writes a record that says only "The operation failed."

```php
// before — app/Machine/Http/Controllers/BatchController.php:287-290

    throw self::failed($i, $op, $e->errorCode, $e->getMessage(), $e->hint, $e->details);

    throw self::failed($i, $op, $e->errorCode, $e->getMessage(), $e->hint, $e->details, $e);
} catch (Throwable $e) {
    throw self::failed($i, $op, 'internal', 'The operation failed.', null, [], $e);
}
```

No `ErrorFile` call is needed here, but not for the reason it first appears. Most op faults never
reach this catch: `dispatchInternal()` runs the op through `$router->dispatch()`, whose routing
pipeline reports the throwable on the spot (N1, under the sub-request's route and the batch's `rid`)
and renders it into an `internal` envelope. The envelope path at `BatchController.php:307` then
throws a cause-less `failed(…, 'internal', …)`. Because `dispatchInternal()` recorded that this
dispatch's fault was admitted, `runOperation()` marks that exception with `ErrorFile::markEcho()`
before throwing it, and `handlerReport()` skips exactly that object (§4.5 step 1). No other
cause-less internal is ever skipped. The rare throw that does reach `:289` now carries
`$previous`, and `handlerReport()` unwraps it to the original throwable. Either way there is exactly
one `[php-machine]` line per internal op fault. A rethrow is compliant (R1).
`SearchController.php:533` and `Envelope.php:177` get the same `$previous`.
`AdminController.php:468`/`:595` do not: they throw after reading a sub-request's HTTP status, with
no throwable in scope (§4.5).

### 8.11 Things that are NOT error sites (do not wrap)

- **A `try/finally` with no catch.** The error propagates; the frame that catches it, or a net,
  reports it.
- **A plain `throw`.** Throwing is not catching. `throw MachineException::invalid(…)` is an answer.
- **A catch that converts to a `MachineException` or `CliError` and throws it.** A rethrow is
  compliant; the handler or the top-level classifier decides whether it is a fault.
- **A gate refusal.** It is a returned response, never a throw (R7).
- **Upstream code**, PHP or JS. It is covered by the nets (§9) and never edited.
- **Tests, fixtures, `mcp/src/canary/`** and the error-file libraries themselves — `app/Machine/ErrorFile/`
  (minus `Canary/`), `errorfile/src`, every `vendor/error-file/` copy and `support/error-file.js`.
  Their catches are the R11 fallbacks (one stderr write, one `console.warn`), which by design never
  report; both coverage scripts exclude these paths (R1, §13).

## 10. Performance design — the per-request PHP model

The PHP web server here is `php artisan serve`, which runs **one** `php -S` process. The application
boots from scratch on every request: there is no worker, no long-lived memory and no timer.
`PHP_CLI_SERVER_WORKERS=4` is set in the justfile but is inert without `--no-reload`, which bring-up
does not pass. So the web writer is one process at a time today — but the design never relies on it:
every write is multi-process safe, because artisan commands, PHPUnit and the two Node clients write
the same file. Changing bring-up is out of scope here.

That model decides the design:

| Concern                     | Decision                                                                                                                                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Happy path, PHP**         | `ErrorFile::for()` stores a string. The provider registers listeners and binds a scoped object; it opens no file. `LogListener::handle()` returns after one level lookup for info and debug records. 100 non-faulting requests open `error.err` zero times (`HappyPathTest`). |
| **Happy path, Node**        | `errorFileFor()` stores a string. Wrappers add one function call. `guard` allocates once, at registration.                                                                                                               |
| **Happy path, browser**     | The core registers four listeners and an interceptor. It makes zero requests when nothing faults.                                                                                                                       |
| **No buffering in PHP**     | There is no process to buffer in, and a fatal never reaches `terminating()`. A record is appended at report time: one `fopen`, one bounded `flock`, one `fwrite`. That is the right cost on a request that is already failing. |
| **Storms in one request**   | L1 turns a repeat into `n++` with zero I/O. 10,000 identical `Log::error` calls in one request cost one line, one L2 write and under 50 ms in total, through the listener's storm fast path (§4.6; `LogListenerTest`).                                                 |
| **Storms across requests**  | L2 turns 500 identical faults from 50 processes into 1 line plus 1 summary. Each process pays one sidecar lock and one small JSON read and write.                                                                       |
| **Runaway distinct faults** | The file budget caps PHP at 600 records a minute, so history cannot rotate away in minutes.                                                                                                                              |
| **Lock contention**         | Every lock wait is bounded at 200 ms, then the record is written anyway (§4.4). No request can hang on the error file.                                                                                                  |
| **Stack cost**              | PHP reads `getTrace()` with args ignored, trims to 12 repo frames, and never calls `getTraceAsString()`. `debug_backtrace` runs only for a T3 record, with `IGNORE_ARGS` and a depth of 30.                              |
| **Out of memory**           | Caps are applied before strings are built; the memory limit is raised by 16 MiB before the FATAL is described.                                                                                                          |
| **Node error path**         | `write` is an array push; a 5 ms unref'd timer appends asynchronously. The only synchronous writes are the flush on `fatal`, exit and signals.                                                                           |
| **Rotation**                | A real-size check per PHP write (one `fstat`), a cached size in Node. A roll is a rename chain of about 1–2 ms, once every 5 MiB.                                                                                       |
| **Bundle**                  | At most 3 KB gzip in the shared chunk; zero dependencies in the core.                                                                                                                                                   |

**What not to do**, because it would hurt performance, and the reviewer rejects it:

- calling `ErrorFile::for()` or `errorFileFor()` in a hot loop (PHP memoises, but it is still a
  lookup per iteration — hoist it);
- building `doing` from values in a loop: put the values in `data`, which is built only on error;
- wrapping a hot inner loop body in `tryOr`: wrap the loop;
- reading `error.err` or `error.fold` from product code: only `ffx logs --errors` reads them.

## 11. Noise control — keeping the file worth reading

A file that fills with answers stops being read. Noise is controlled at five layers:

1. **Refusals write nothing** (R7): a `MachineException` other than `internal`/`upstream_error`,
   upstream's `dontReport`, every gate refusal, every `CliError` and `ToolError` answer, a
   `ConfigError`, and a browser 401/404/419/422/429.
2. **Upstream's log is tiered** (§4.6). Warnings are dropped unless verbose. Trace continuations, the
   `MailError` dump and deprecations are always dropped. The 36 expected prefixes are dropped. The
   render duplicate is dropped. A bare error string is WARN, not ERROR.
3. **Bursts fold** (R10, §4.7) in two layers, with lazy summaries, a 1,000-key cap and a 600 a minute
   budget.
4. **Transient network errors in Node fold per 10 minutes at WARN.** `ECONNREFUSED` while `ffx up` is
   still waiting for the server is not a fault storm.
5. **Benign browser conditions are filtered** (§6.3): ResizeObserver, `Script error.` with no Error
   object, Vite HMR, anything after `pagehide`.

**The replay gate measures it before it ships.** `scripts/error-file-replay.php` feeds today's
`storage/logs/ff3-*.log` through the `Classifier` offline and prints **counts per tier only, never
lines**. The gate is meant to show that a normal day classifies to 10 written lines or fewer before
T2 and T3 are switched on; its first run and the decision taken on it are in §16.2. It reads private
logs at runtime and prints only counts, which the private-data rules allow.

## 12. Privacy, redaction and open-source safety (LOCKED)

This repo is public. The ledger is not. The error file lives **outside** the repo, in `~/T/`, at mode
`0600`. On top of that, the libraries apply these defences, so a call site cannot get privacy wrong —
and neither can the 425 upstream log strings that the log net turns into call sites.

1. **Never read.** Request bodies, query strings, headers, cookies, `request()->all()`, log context
   arrays except `context['exception']`, trace `args`, `getTraceAsString()`, the `server.log` tail,
   `.env` values — with exactly the named exceptions of R12: `X-Firefly-Request-Id` and
   `X-Firefly-Client` in `Context.php`; `Host`, `Origin`, `Sec-Fetch-Site`, `Content-Type` and
   `Content-Length` in `Http/ErrorReportGate.php`; and the capped `php://input` read of the ingest
   body in `Ingest.php` (plus the non-request `$_SERVER['HOME']` and `$_SERVER['argv']` reads named
   in §4.1). `SourceCanaryTest` greps the library for each accessor and allowlists only
   those files and calls (§4.1).
2. **SQL.** Bindings are masked at the source: the provider sets
   `mask_bindings_in_exception_messages = true` on every connection. The writer also cuts a
   `QueryException` message at ` (Connection: `, which drops the SQL text. Two independent layers.
3. **Data keys** are checked case-insensitively:
   - `SECRET_KEY = /pass(word)?|secret|token|auth|cookie|session|key|signature|credential|bearer|csrf|xsrf/i`
     → the value becomes `[redacted]`;
   - `LEDGER_KEY = /amount|balance|payee|notes?|memo|account_?name|category_?name|description|imported_payee|statement|iban|bic|account_?number|source_?name|destination_?name|opening_balance|virtual_balance|foreign_amount|internal_reference|sepa_/i`
     → the value becomes `[ledger-field refused]`, even when it is null.
   Only opaque ids, counts, booleans, route names, codes and statuses are meant to pass. The broad
   `name`, `path`, `file` and `tags` keys are not refused, because the value scrubs cover them.
4. **Text values** — the error, every cause and every data value — pass these scrubs, in this
   order. `where` and `doing` are not scrubbed; they are **templated or literal** instead (rule 6):
   1. the ` (Connection: ` cut (`Redactor::SQL_CUT`, and the same constant in `redact.ts`). It is
      specific to Laravel's `QueryException` but, because `Redactor::text()` does not know the
      class, it applies to **any** text containing ` (Connection: `: the span from ` (Connection: ` up to,
      not including, a trailing ` (code=…)` or the next ` | cause: ` is removed, so it can run on a whole headline or cause chain
      after `Describer` (golden record 12 exercises it);
   2. URL query values for `token code state key password secret signature sig api_key access_token`
      → `[redacted]`, keeping the parameter names;
   3. hex runs of **32 or more** characters → `[REDACTED-KEY]`. This catches the 64-hex machine key
      and upstream's 32-hex CLI access tokens (`bin2hex(random_bytes(16))`);
   4. IBAN shapes → `[iban]` (so `GB82WEST12345698765432` never appears);
   5. email shapes → `[email]`;
   6. decimal amounts `(?<![\w.])-?\d{1,15}\.\d{2,12}(?![\w.])` → `[amount]`; a version string such
      as `6.1.20` does not match;
   7. digit runs of 9–17 → `[number]` (a card number, an account number);
   8. `(/Users|/home)/<name>` → `~`, and the repo's absolute base path → nothing.
   The amount and digit rules cost a little diagnosis — `Allowed memory size of [number] bytes` — and
   that cost is accepted.
5. **T3 payloads.** The withhold-after list and `PayloadGuard` (§4.6).
6. **`doing` and `where` are literals**, enforced by the coverage scripts. Net records use route
   **templates**, never raw paths. A browser net record's `where` and `doing` are built by
   `templatePath()` (§6.4): at most two leading static segments (one after `api/v1/`) survive, and
   every other segment becomes `{x}`, so `/tags/show/Synthetic Tag` is written `/tags/show/{x}`.
7. **The browser is re-redacted and re-checked.** Ingest runs rules 3 and 4 on every event and
   applies its closed `where`/`doing` rules (§4.10): a page-path `where` is re-templated with
   `templatePath()`, any other `where` must be on the fork-module allowlist, `doing` must be a closed
   browser phrase or `calling {METHOD} {path}` with only the path part templated, and anything else
   becomes `{x}`. It never trusts the browser.
8. **Nothing from `error.err` enters the repo.** No fixture, snapshot, doc example or commit message
   may contain a real line. Every example in this spec is synthetic.

**Parity.** The same regexes exist in `app/Machine/ErrorFile/Redactor.php` and

## 13. Enforcement — two coverage scripts and the canaries

A rule that nothing checks is a rule nobody follows (§1.4). Both scripts write into
`error_file_coverage.json` next to the error file (keys `php`, `js`, `runtimes`), preserving the
other keys, and exit non-zero on any enforced violation. `just check-errors` runs both. Both are
plain scripts with no Laravel boot, so they resolve the report path with the §3.1 **Node** rule:
`FIREFLY_ERROR_FILE` from the process environment (`~/` expanded), else `$HOME/T/firefly/`, else
`<tmp>/firefly_<uid>/`. A `FIREFLY_ERROR_FILE` set only in `.env` is not seen, as §3.1 says. Both
take `--quiet` (totals and violations only), and so does the recipe.

### 13.1 `scripts/error-file-coverage.php` (php-parser)

It uses `vendor/nikic/php-parser`, which is already installed.

**Enforced scope:** `app/Machine/**/*.php`, minus `app/Machine/ErrorFile/` (V9, §16.5), plus the
fork's commands in `app/Console/Commands/Machine/**/*.php` (R1). A `Catch_` node is
**compliant** when its body contains any of: a `Throw_` (statement or expression); a call
`ErrorFile::for(<string literal | self::WHERE>)->{caught|warn|expected|rethrow|fatal|tryOr}(<string
literal>, …)`; or a call to `report(`. Violations are:

- `wrongWhere` — the literal (or the class's `WHERE` constant) is not the file's repo-relative path;
- `dynamicDoing` — the first argument is not a string literal;
- `badDoing` — the literal does not match `/^[a-z][A-Za-z0-9 ,'-]*[A-Za-z0-9]$/` (a gerund phrase, no
  trailing period, R2);
- `ledgerKey` — a literal data key matches `LEDGER_KEY`;
- `unreported` — none of the compliant forms is present.

`// expected:` comments and `Audit::line()` are **not** compliant forms: a comment records nothing
under VERBOSE, and an audit line is not a fault record.

**Informational scope:** upstream `app/` (about 1,211 files), minus the fork-owned paths above. Each catch is classed `log_error`,
`log_warning`, `rethrow`, `debug` or `silent`, by precedence: an error-level log or `report()` →
`log_error`; else a warning or notice → `log_warning`; else a throw → `rethrow`; else debug or info →
`debug`; else `silent`. Today that gives 306 catches: 186 `log_error`, 23 `log_warning`, 38
`rethrow`, 21 `debug`, 38 `silent` — the total and the silent count (the one AC 18 names) match
§4.6's survey exactly; the two-catch `log_error`/`debug` difference is classification detail (for
example a catch that logs at debug through `app('log')` or `logger()`). Silent catches are listed by `file:line`; the output
prints the change since the previous run (`previous.upstream` in the JSON), so a merge that adds a
silent upstream catch shows up. Informational findings **never** fail the run: upstream is covered by
the nets and is never edited.

### 13.2 `scripts/error-file-coverage.mjs` (the TypeScript compiler API)

It loads `typescript` from `cli/node_modules` and reads syntax only — no type is ever asked for and
nothing is emitted. `cli/node_modules/typescript` is TypeScript 7 (the native compiler), whose JS API
(`typescript/unstable/sync`) has **no** `createSourceFile`: a syntax tree is reachable only through a
`Program`. So the script opens **one** in-memory project — a virtual tsconfig served through the
API's fs callbacks, never written to disk (`allowJs`, `noResolve`, `noLib`, `types: []`) — holding
exactly the in-scope files, and walks each `program.getSourceFile()` tree with `forEachChild` and
`SyntaxKind`. A run takes about 1 s. If `cli/` ever pins TypeScript 5 or 6 again, plain
`ts.createSourceFile` is the simpler equivalent. It scans `cli/code/src` (minus `vendor/`), `mcp/src` (minus `vendor/` and `canary/`,
which is test-probe code) and `resources/assets/v3/js` (minus the browser core
`support/error-file.js`). The error-file libraries — `errorfile/src`, every `vendor/error-file/`
copy and `support/error-file.js` — are **excluded**, as `app/Machine/ErrorFile/` is in §13.1 and as
AB excludes `packages/error-file/src/`: their catches are the R11 fallbacks, which must not report
(R1, §8.11). It inspects `CatchClause`,
`.catch(fn)`, `.then(_, fn)`, `addEventListener('error' | 'unhandledrejection', fn)` and
`onerror =`. Accepted forms: `errors.*` or `*Errors.*` calls; the wrappers; `throw`;
`Promise.reject`; a call to a name ending `OrThrow`. On top of that, the same violations as §13.1:
`wrongWhere` — the literal passed to `errorFileFor('<x>')` is not the file's own repo-relative path
(R14); `dynamicDoing` — `doing` is not a string literal; `badDoing` — the literal fails the R2 regex
`/^[a-z][A-Za-z0-9 ,'-]*[A-Za-z0-9]$/`; `ledgerKey` — a literal data key matches `LEDGER_KEY`.

The exclusion of the error-file libraries narrows D8, which named `errorfile/src` as enforced
scope; it is recorded as V9 (§16.5).

**Upstream v3 files get a count ceiling.** A committed `scripts/error-file-coverage.upstream-v3.json`
maps `{ "<file>": <catch-site count> }` for today's 26 sites in 20 files. A file at or below its
entry is `upstream-net-covered`. A higher count, or a new upstream file with any catch site, is
`violating`, and the message tells the operator to confirm that N18/N19 cover the new site and to
raise the entry. A merge that adds an upstream catch therefore goes red and demands a decision,
without anyone editing upstream. `--update-ceiling` rewrites the ceiling file from today's counts
(this is how the committed file was generated); a ceiling entry **above** today's count, or one for a
file that is gone, prints a `note` and never fails, so the ceiling can be kept exact (P4). The fork-owned glue `support/error-file-app.js` is enforced
normally; the core `support/error-file.js` is the library and is excluded (above).

**Session views with no bundle (informational).** The script also lists every Blade view that
extends `layout.v3.session` and has no `@vite('js/pages…')` entry — today the six views of escape
hatch E11 — and prints the change since the previous run. It never fails on them; it makes a merge
that adds one visible.

## 15. Testing

PHP tests run in the machine suite (`phpunit.machine.xml`) with the path set per test by
`ErrorFile::usePath($this->sandbox.'/error.err')` — the env-derived `errorfile.path` is ignored
under PHPUnit (R13) — and `MachineTestCase::setUp()` calls `ErrorFile::resetForTests()`. Node tests
use `node:test`. Nothing ever writes the real file (R13).

**Child processes.** `usePath()` does not reach a `proc_open` child, and the child inherits
`APP_ENV=testing` and the force-blanked variables. So `FatalChildTest` and `ConcurrencyTest` pass an
**explicit child env**: `FIREFLY_ERROR_FILE=<sandbox>/error.err` and
`FIREFLY_ERROR_FILE_TEST_PATH=<sandbox>/error.err` (the second is what `Paths` honours under
`runningUnitTests()`), plus `FIREFLY_ERROR_FILE_CANARY=1` for the artisan canary `fatal`, which
refuses to exist otherwise (§4.11, §13.4). Without that env the children would write nothing and
the tests would fail for no visible reason.

**Node in-process tests.** They pass an explicit `file:` to `installNodeErrorFile()` and reset it
afterwards (§5.5); spawned children get `FIREFLY_ERROR_FILE` from the sandbox env.

**Test processes never reach the real directory.** `just test` exports `FIREFLY_ERROR_FILE` to a
fresh canary path for every line of the recipe, and its last line fails if that path exists (§5.4,
AC 11): any test process that falls back to the environment instead of its sandbox path is caught.
`~/T/firefly/` itself is **not** snapshotted, because live runtimes may legitimately write there
during a run — the operator's user-scope `firefly_iii` MCP server inside a Claude Code session, and
a web app left running by `ffx up`, including a PHP lazy summary or an `error.fold` rewrite. A stat
check on the real directory would fail `just test` for reasons that have nothing to do with the
tests.

### 17.2 How an upstream change is caught

- **The nets make most merges free.** A new upstream `Log::error` is captured with no edit. A new
  upstream exception is reported through the handler with no edit.
- **`UpstreamAnchorsTest`** asserts, one fact per method, each with a message naming the section to
  revisit: `Handler` extends Laravel's handler; `$dontReport` contains `HttpException`;
  `MailError.php` contains `'Exception is: %s'`; `QueryException.php` contains `' (Connection: '`;
  `Connection.php` reads `mask_bindings_in_exception_messages`; `MessageLogged` has `level`,
  `message` and `context`; `app(ExceptionHandler::class) instanceof MachineExceptionHandler`; both
  boot files carry the marker line; `boot/axios.js` exports `api`; the error-file routes are
  registered before the plane's `{machine_any?}`.
- **`ExpectedListDriftTest`** fails when upstream rewords an expected message. The failure is safe:
  the line becomes a WARN until the needle is updated.
- **The v3 ceiling** fails when upstream adds a catch site (§13.2).
- **`just check-delta`** (`scripts/upstream-delta.mjs` + `scripts/upstream-delta.allow`) fails when a
  modified upstream path since `merge-base HEAD upstream/develop` is not in the allowlist. It scans
  the **whole** tree, minus the class-C paths of §17.1 — not only `app/`, `bootstrap/`, `config/` and
  the like, because §17.1's zero-modified list names top-level files (`.env.example`,
  `package.json`, `vite.config.js`, `eslint.config.mjs`). A deleted (D) or type-changed (T) path
  counts as modified; added and untracked paths are printed as class B. With no `upstream` remote it
  prints a note and exits 0; with an `upstream` remote whose `develop` is not fetched it exits 1.
  `--base <commit>` runs it against an explicit base without a remote.

Handles: failing when a modified upstream path is not on the allowlist.
Code: `~/BGit/Bryan_git/firefly-iii/scripts/upstream-delta.mjs` — the delta check behind `just check-delta` (to be created)
Code: `~/BGit/Bryan_git/firefly-iii/scripts/upstream-delta.allow` — the class-A allowlist (to be created)

### 17.3 The post-merge playbook

After `git merge upstream/develop`:

1. `just check-delta`.
2. `php vendor/bin/phpunit -c phpunit.machine.xml --filter 'UpstreamAnchors|ExpectedListDrift|HandlerHook'`.
3. `just check-errors` — read the upstream-delta line and any new v3 ceiling violation.
4. `just build && just check-errors --canary`.

A conflict in a boot file resolves as "take upstream, then re-add the one marker line".

## 21. Invariants recap (LOCKED)

1. One file for every runtime: `~/T/firefly/error.err`, moved only by `FIREFLY_ERROR_FILE`.
2. One line format, two implementations (PHP and TypeScript), one golden fixture, byte for byte.
3. Zero work until a fault. No syscall on `~/T/firefly/` on the happy path.
4. Each throwable is written once. A burst is one line plus a count, across processes.
5. A refusal is an answer, not a fault: gate refusals, plane answers, `dontReport`, expected upstream
   log lines and browser 4xx answers write nothing. Expected failures are still marked at the site.
6. PHP writes synchronously at report time. A fatal is on disk before the process dies.
7. Every lock wait is bounded. The file never takes the app down, never recurses and never reports
   its own failure.
8. The browser delivers; it never writes. The ingest route is loopback-only, same-origin, write-only,
   capped, rate-limited, and always answers `204`.
9. No secret and no ledger value is ever written. The library never reads a body, a query string, a
   header, a context array or a trace arg — except the named ones: `X-Firefly-Request-Id` and
   `X-Firefly-Client`, the ingest gate's `Host`/`Origin`/`Sec-Fetch-Site`/`Content-Type`/`Content-Length`,
   and the capped ingest body.
10. `doing` and `where` are literals or route templates, never raw values.
11. Tests never write the real file.
12. Upstream PHP is never edited to report. The upstream delta is two import lines, each marked
    `// fork: pm/error_err.mdx`.
13. Coverage is proven by two scripts and fifteen canaries, not by convention.
14. Every fault hint says: `The detail is in ~/T/firefly/error.err — ffx logs --errors`.
